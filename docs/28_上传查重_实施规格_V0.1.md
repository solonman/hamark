# 28 上传查重（同一文件＋同一内容不同来源）实施规格 V0.1

状态：已冻结（2026-11-13，项目负责人在对话中确认）
分支：`upload-dedup` → 合 main 推送

## 一、要解决的问题

现在各库上传不查重：同一个文件传两次就有两条条目、两份存储对象；同一条广告从抖音、B 站、官网各下一份，更是认不出来。

本期只做**提醒**，不拦截：发现重复时在上传对话框里当场说清「这个文件／这段内容已在《某某》里」，给「打开那条」和「仍要上传」，由上传人自己决定。

## 二、已定口径

| # | 口径 |
|---|---|
| 1 | 只提醒、可继续上传；不做归并、不做「用这条替换那条」。 |
| 2 | 只在**同一个库**内比。复盘库的素材与录音算同一个库。 |
| 3 | 已删除、已移除、已放弃、没传完的条目不算。测试数据（`data_scope <> 'BUSINESS'` 的视频）不算。 |
| 4 | **只给新上传算指纹**。老数据不补算（补算要从 COS 再下载一遍，属于付费操作，另行批准）。 |
| 5 | 老数据退一步只比「字节数」：大小完全相同就给弱提示「疑似重复」，同名时写明同名。 |
| 6 | 覆盖入口：视频库新建、视频换片、报告库、公共视觉素材、复盘库素材、复盘库录音、老孙点评录音／文档。**报告的「相关资料」附件不查**（同一份 brief 挂在多份报告下是正常用法）。 |

## 三、两层判断

### 3.1 同一个文件（所有类型）

1. **初查用字节数**：字节数不同，内容一定不同，直接放过。
2. **确认用抽样指纹**：SHA-256（字节数 8 字节小端 ＋ 开头 2MB ＋ 正中 2MB ＋ 末尾 2MB）；6MB 以内的文件对全文算。浏览器自带的 `crypto.subtle` 算，不引入依赖。
3. 抽样指纹相同 → 「同一个文件」。

### 3.2 同一内容、不同来源（视频与图片）

针对同一条片子从不同渠道下载：重新压缩、改分辨率／帧率、角落水印、黑边、平台片头片尾、镜像。

- **视频**：浏览器解码本地文件，从 0.5 秒起每秒抽一帧，最多前 180 帧。
  1. 每帧缩成小灰度图（长边 160）；在八成以上「有画面」的帧里都暗且均匀的行／列视为黑边，裁掉。纯色帧不参与投票——平台加的整屏片头片尾没有黑边，若要求「每一帧都是」，正好会把要认的情况漏掉。
  2. 只取剩下画面的中间 75%（四边各让 12.5%），避开角标水印。
  3. 缩到 32×32 做 DCT，取左上 8×8 低频（去掉直流）对中位数二值化，得 64 位感知哈希；画面几乎全平（纯黑转场）的帧记为空。
  4. 比对：两段帧序列在 ±15 秒范围内逐秒错位对齐，汉明距离 ≤ 12 算一帧对上；对上的帧数 ÷ 较短一段的有效帧数 ≥ 60%，且至少 3 帧，判为「内容相似」。新文件同时用左右镜像后的哈希再比一遍，取较高者。
- **图片**：同样裁掉四周均匀色边、取中间 75%、64 位感知哈希；新图（含镜像）与库里图片的汉明距离 ≤ 10 判为「内容相似」。
- 浏览器解不了的格式（如 Chrome 里的 HEVC、HEIC）只做 3.1，不报错。
- 抽帧总时长上限 20 秒，到点用已抽到的帧；提交时最多等比对 30 秒，到点照常上传。只提醒的功能不能拖住上传。

识别不了：横版改竖版的大幅裁切、模糊背景填充、加速搬运、画中画（规格外，写进提示文案之外的说明里即可）。

## 四、数据

新增一张表 `upload_fingerprints`（附加式迁移 `web/db/migrations/2026-11-13-upload-fingerprints.sql`，生产在 SQL 编辑器整段执行）：

| 列 | 说明 |
|---|---|
| `source` + `target_id` | 指纹属于哪张表的哪一行，唯一。source ∈ VIDEO / REPORT / VISUAL_ASSET / RETRO_ASSET / RETRO_RECORDING / AUDIO_REVIEW |
| `library` | VIDEO / REPORT / VISUAL / RETRO / AUDIO_REVIEW，由 source 决定 |
| `file_size`、`sample_sha256` | 3.1 |
| `media_kind` | VIDEO / IMAGE / FILE |
| `frame_hashes` | 3.2 的感知哈希，空格分隔的 16 位十六进制，空帧写 `-` |
| `width`、`height`、`duration_ms` | 提示里并排展示用 |
| `algorithm_version` | `upload-fp/1`，以后改算法时只和同版本比 |

视频换片后，同一视频的指纹整行更新为新文件。表缺失（生产尚未迁移）时，查重接口返回「没发现」、登记接口静默跳过，上传照常。

## 五、接口

- `POST /api/upload-dedup/check`：`{ library, excludeOwnerId?, files: [{ key, size, name, sha?, kind, hashes?, mirrorHashes?, width?, height?, durationMs? }] }` → `{ results: { [key]: Match[] } }`。每个文件最多返回 5 条，按「同一个文件 ＞ 内容相似（相似度降序）＞ 疑似（大小一样）」排。
- `POST /api/upload-dedup/record`：`{ source, targetId, fingerprint }`。只有该行的上传人能登记（视频／报告看 `created_by_email`，视觉素材看所属案例创建人，复盘素材看 `created_by_user_id`，复盘录音看 `uploaded_by_user_id`，老孙点评看 `reviewer_user_id`）。失败不影响上传。
- 两个接口都要求登录与同源。

## 六、界面

- 选好文件后立刻在对话框里算指纹并比对，文件区下方出一块提示：
  - 比对中：「正在比对是否已传过…」（不挡操作）。
  - 发现重复：琥珀色提示块，逐条列出「同一个文件／内容相似（约 N% 的画面对得上）／疑似重复（大小完全一样）」＋《标题》＋上传人＋日期＋分辨率，每条带「打开那条」（新标签页）。底部按钮「仍要上传」。
- 有未确认的重复时点提交：不发请求，提示「先看一下上面的重复提示，确认后再上传」。比对还没结束时点提交：等比对结束再决定。
- 同一次选了两个一样的文件（多文件对话框）也提示。
- 选完文件就直接开传的入口（复盘附件格、复盘录音、老孙点评）：先停住比对，没发现就自动开传；发现了等「仍要上传」。复盘附件格不在对话框里，另给「不传了」。
- 视频库新建与换片这两个框是写死的浅色纸底，提示块在其中固定用浅色主题的琥珀色（`paper`）。
- 提示块是共用组件 `components/shared/DuplicateUploadNotice.tsx`，样式用 `--v04-*` 变量。

## 七、验收清单

1. 同一视频传两次，第二次选完文件即出现「同一个文件」，可打开那条，可「仍要上传」后成功入库。
2. 同一视频转码（改分辨率、加黑边、加角标、前面加 3 秒片头、镜像）后上传，出现「内容相似」。
3. 同品牌不同的两条片子不报相似。
4. 删除那条后再传，不再提示。
5. 老数据（无指纹）同字节数出现「疑似重复」。
6. 表不存在时上传不受影响。
7. 各入口（第二节 #6）都接上；`npm test`、`npm run lint`、`npm run build` 通过。

## 八、本机验收记录（2026-11-13）

用本机演示库里的真实广告《欢迎回家》（98 秒，952×720）做素材，ffmpeg 生成各变体：

| 情况 | 结果 |
|---|---|
| 原文件再传（老数据，无指纹） | 疑似重复（大小完全一样）→《欢迎回家》 |
| 未确认就提交 | 停住，提示「先看一下上面的重复提示…」；点「仍要上传」后入库并登记指纹 |
| 搬运版（640×360、上下黑边、角标、3 秒整屏片头） | 内容相似，约 93% 的画面对得上 |
| 镜像版（左右翻转、960 宽） | 内容相似，约 100% |
| 无关测试片 | 无提示 |
| 原文件再传（已有指纹） | 同一个文件 ＋ 老数据那条疑似重复 |
| 删掉那条之后 | 镜像版无提示；原文件只剩老数据那条 |
| 报告：同一 PDF 再传 | 同一个文件 |
| 公共视觉：同批选两遍／缩小加白边加角标／镜像 PNG／原图 | 这次选了两遍／画面相似／画面相似／同一个文件 |
| 复盘附件：别的案例里的同图／转发版 | 停住提示；「仍要上传」开传；「不传了」不加 |
| 复盘录音：同一录音传到另一案例 | 同一个文件，「仍要上传」后开传 |
| 老孙点评：首传自动开传并登记；同一录音的服务端比对 | 同一个文件 |
| 非上传人登记指纹 | 403 |
| 指纹表不存在 | 查重退回只比字节数，登记返回 NO_TABLE，上传不受影响 |

离线同算法核对（ffmpeg 每秒一帧）：搬运版 98/98 帧对上，镜像版 98/98（镜像哈希），无关片 0；同一条片子相隔 40 秒的两帧哈希距离 40（阈值 10）。
未在浏览器里走通的：视频换片对话框（与新建同一套接法，类型检查通过）；老孙点评的「第二份作业传同一录音」（本机演示身份建不出第二位同事的版本，改用接口核对）。
