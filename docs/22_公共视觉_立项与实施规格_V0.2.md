## 一、范围

做三件事，按这个顺序：

1. **地基**：`visual_cases` 一族表、图片上传与派生图链路、视频复用现有链路、上传与 complete 接口。
2. **公共视觉库**：首页「公共视觉库」页签，包括上传、三个子领域筛选、搜索、按收藏排序、只看我收藏的。
3. **案例详情**：一个页面同时承载混合载体，包括舞台加素材条、正文、案例信息。

明确不做的见第八节：逆向拆解、作业与评分、版本链、评审、AI。

## 二、定位与命名

### 2.1 一句话定位

公共视觉是**案例收集频道**，不是能力训练域。前两个域的价值在用户产出的拆解内容；本域的价值在**案例条目本身**。上传完成就闭环，不要求用户交作业。

### 2.2 命名

| 项 | 取值 | 说明 |
|---|---|---|
| 中文名 | 公共视觉 | 页签名与页面标题统一用「**公共视觉库**」，与「视频库／报告库」并列 |
| domain_key | `PUBLIC_VISUAL` | 与 `videos.domain_key = 'AD_VIDEO'` 同一命名空间，但**本域不建专业域契约** |
| 页签参数 | `?library=VISUAL` | 列表页复用首页页签，不新开目录 |
| 详情路由 | `/visual/[id]` | |
| 接口前缀 | `/api/visual-cases` | 与 `/api/videos`、`/api/reports` 平行 |

### 2.3 与 A0.1 的关系（本域**不**登记为 ProfessionalDomain）

公共视觉没有标注体系、没有标准版本、没有评分量表。A-003 要求「所有结果绑定专业域和标准版本」，如果硬登记一个没有标准的域，这条原则就只剩名义上合规。

所以本轮采用**频道级接入**：

- 不建 `professional_domains` 登记行，不引入 `DomainSchemaVersion`／`taxonomy_version`；
- 不挂视频侧的 V0.4 契约（`collaboration_workspaces`、`annotation_vocabulary_versions` 那套），理由与 `db/report-schema.ts` 顶部注释一致：那套契约是为镜头字段服务的，硬挂只会把两边绑死；
- 数据沿用报告域的先例：**独立表族 + 元数据 JSON 列**，不建万能字段表（A-002）。

将来公共视觉有了真正的标注标准，再按 A-003 补登记；本轮的 `subdomain` 与 `metadata_json` 不会因此返工。

### 2.4 「公共」的边界

**公司内部全员可见**，与视频库、报告库一致。不提供匿名公开链接，不对外分享。

理由：`README_同事接手必读.md` 与 A0.1 的既有口径是"仅限公司内部学习，不得发布为匿名公开资源"。将来如果要对外，性质、版权、审核口径都要另写一份规格，不在本文范围内。

## 三、冻死的产品规则

### 3.1 子领域（三个，单选，必填）

| 键 | 中文 | 典型内容 |
|---|---|---|
| `OOH` | 户外广告 | 装置、互动装置、裸眼 3D、公交/地铁/楼宇媒体、快闪空间 |
| `PUBLIC_ART` | 公共艺术 | 雕塑、壁画、城市家具、临时展陈、公共空间的介入作品 |
| `RETAIL` | 商业展陈 | 门头、围挡、橱窗、快闪店、商业空间的装置与陈列 |

词表**固定三选一**，不做后台可配置。子领域同时是列表页的筛选维度。

### 3.2 载体（三种，可混合）

| 载体 | 存放位置 | 约束 |
|---|---|---|
| 视频 | `visual_case_assets.type = 'VIDEO'` | 每案例 0–12 段，**可以多段**（现场视频、不同机位、不同时段的投放） |
| 图片 | `visual_case_assets.type = 'IMAGE'` | 每案例 0–24 张，可以只有图片（没有视频、没有正文） |
| 文本 | `visual_cases.text_body` | 每案例最多 1 段；纯文本，保留换行；**不解析 `#标签`、不做 Markdown、不做富文本编辑器** |

规则：

1. **至少有一种载体**才算填完：视频、图片、正文三者至少有一样不为空。
2. **不要求用户先选"载体类型"**。卡片和详情上的**载体摘要**（如「视频 2 · 图片 3 · 文字」）在查询时按计数推导，不入库，也不设 `case_kind` 枚举。先选类型会立刻分裂出三套表单，而且和"混合载体"矛盾。
3. 允许的典型组合：`视频 + 图片 + 文本`（互动装置的标准形态）、`图片 + 文本`（公共艺术）、`图片`（门头、围挡）、`文本`（纯文字条目）。
4. **一条混排的素材序列**：视频和图片排在同一条序列里，顺序就是 `position`。默认按添加顺序排；用户在上传／编辑对话框里用「⤒ 设为封面」「← →」调整。**封面只有一条规则：第一位素材**。「设为封面」就是把它挪到第一位，不另外存封面指针。
5. **详情页是一个舞台加一条素材条**。所有已传完的素材按 `position` 排成一条，舞台显示选中的那一个（视频显示播放器，图片显示 1600w 展示图），首屏选中第一位。所以纯图片案例首屏就是第一张图；纯文字案例没有舞台；多段视频不折叠，每段在素材条上各占一格。

### 3.3 上传时要填的信息

**通用必填**（四项封顶，见决定 #7）：

| 字段 | 控件 | 约束 |
|---|---|---|
| 子领域 | 下拉（同报告上传的「任务类型」） | 见 3.1；选了之后，「补充信息」里出现该子领域的专有字段 |
| 标题 | 单行 | 1–80 字 |
| 采集地点 | 单行 | 1–60 字，**必填、拦提交**；提示写"城市 · 场地，写到城市即可"；不设"未知"选项 |
| 标签 | 逗号分隔的文本框（同视频、报告上传） | 至少 1 个，见 3.3.1 |

**通用选填**（放在「补充信息（选填）」折叠区里）：创作方／品牌、首次投放或落成时间（`YYYY-MM` 或 `YYYY`，原文保存）、一句话摘要、来源链接、版权／拍摄说明（默认"仅公司内部学习使用"，可以改写）。**不加**视频上传那种必勾的"仅用于公司内部学习"确认项（决定 #17）。正文虽然是选填，但不折叠，因为纯文字案例靠它成立。

#### 3.3.1 长度与格式

| 字段 | 规则 |
|---|---|
| 标题 | 1–80 字 |
| 采集地点 | 1–60 字 |
| 创作方／品牌 | ≤60 字 |
| 一句话摘要 | ≤60 字；留空就不显示，**不自动截取正文**顶替 |
| 标签 | 1–10 个，每个 ≤20 字；中英文逗号都能分隔；去首尾空白、NFKC 归一（全角转半角）；同一案例内忽略大小写和空格去重（「裸眼 3D」和「裸眼3d」算同一个，保留先写的那个） |
| 正文 | ≤20000 字 |
| 来源链接 | ≤500 字；**只收 `http://`、`https://`**，其他协议一律 400；渲染成 `target="_blank" rel="noopener noreferrer"` 的链接 |
| 时间 | 原文保存，不解析 |

#### 3.3.2 子领域专有字段

写在 `metadata_json`，全部选填。冻结的是字段名与选项，新增项按 3.4 的规则走。控件：单选用下拉，多选用药丸，文本用单行框。

| 子领域 | 字段 | 键 | 类型与选项 |
|---|---|---|---|
| 户外广告 | 媒体形式 | `mediaFormat` | 单选：地铁 ／ 公交 ／ 楼宇 ／ 户外大牌 ／ 裸眼 3D ／ 快闪空间 ／ 其他 |
| | 互动方式 | `interactionType` | 多选：体感 ／ 触摸 ／ AR ／ 声音 ／ 扫码 ／ 人脸识别 ／ 机械动作 ／ 其他（不互动就都不选） |
| | 技术与材料 | `techNotes` | 单行（LED、投影、雾幕、镜面…） |
| | 投放周期 | `campaignPeriod` | 单行 |
| 公共艺术 | 作品类型 | `artType` | 单选：雕塑 ／ 壁画／涂鸦 ／ 装置 ／ 城市家具 ／ 临时介入 ／ 其他 |
| | 材质 | `materials` | 单行 |
| | 尺度 | `scale` | 单行（如"12m × 4m × 6m"） |
| | 是否永久 | `permanence` | 单选：永久 ／ 临时 ／ 已拆除 |
| | 委托方／策展方 | `commissioner` | 单行 |
| 商业展陈 | 展陈位置 | `displayVenue` | 单选：门头 ／ 围挡 ／ 橱窗 ／ 中庭 ／ 快闪店 ／ 其他 |
| | 展陈周期 | `displayPeriod` | 单行 |
| | 主材 | `displayMaterials` | 单行 |
| | 制作方 | `producer` | 单行 |

V0.2 删掉了两个字段（决定 #15）：户外广告的「是否互动」`interactive`（由「互动方式」是否为空推出）；商业展陈的「品牌」`brandName`（与通用「创作方／品牌」重复，原来还要靠"两个都填以哪个为准"兜底）。这两个字段还没上线，删掉不涉及数据迁移，`metadata_schema_version` 仍是 `visual-metadata/1`。

### 3.4 元数据扩展规则（**四、五节写代码时不得违反**）

`metadata_json` 是开放的，但要守规矩：

1. 冻死的键（上表）在各子领域内**不得改名，不得改语义**；要改语义必须升 `metadata_schema_version`。
2. 新增专有项就是新增键，不改已有键；每新增一个键，必须同步更新本文档的表格和 `lib/visual-metadata.ts` 的字段清单。
3. **不做后台可配置的词表**。字段少（每个子领域 4–5 项）、变更慢，做成可配置会引入一套管理界面和审计成本，得不偿失。哪天某个子领域的字段需要非工程人员频繁改，再单独提。
4. 值的类型：单选和文本存字符串；**多选存字符串数组**；布尔写成 `"true"` / `"false"`（当前没有布尔项）。空值不写键。
5. **未知键**：写入时（POST／PATCH）**拒绝**，不属于当前 `subdomain` 字段清单的键一律 400，并报出键名；读取时，库里已有的未知键（旧版本遗留）原样保留，不展示。
6. **换子领域**：前端切换时丢掉旧子领域的整组专有字段；服务端按第 5 条兜底。

### 3.5 上传后的处理

| 载体 | 处理 | 状态 |
|---|---|---|
| 视频 | **不转码**，沿用现有 `stream` 路由与 COS 预签名；封面沿用浏览器截帧（`video-thumbnail.ts`，最宽 1600）；时长、宽高由浏览器读元数据后上报 | 素材级 `upload_status`；封面传完后 `derivative_status` 即为 READY |
| 图片 | 原图直传；生成两档派生图：约 480w 的缩略图（卡片、素材条）和约 1600w 的展示图（舞台、大图查看）；原图只在点「查看原图」时才签名 | 素材级 `upload_status` + `derivative_status` |
| 文本 | 无文件，无处理 | — |

**格式**：图片收 JPEG／PNG／WebP／HEIC／HEIF。HEIC 是 iPhone 的默认格式，派生图统一出 JPG；「查看原图」遇到 HEIC 时以附件形式下载，因为浏览器打不开。不收 SVG（可以夹带脚本），GIF 动图另议（十.2）。视频同视频域：不限格式和大小，能不能在网页里直接播放取决于浏览器。

**派生图怎么生成**（决定 #4，2026-09-19 修订）：

- **生产**：complete 确认原图到位后，服务端对每张图提交一次数据万象**持久化处理**（云上数据处理，规则如 `imageMogr2/auto-orient/thumbnail/480x/format/jpg`，1600w 同理），结果写回 4.3 的 `thumb.jpg`／`display.jpg`，不需要再起一台离线机器。
- **本机**（`LOCAL_DEMO_MODE`，没有真 COS）：退回离线脚本 `npm run visual:derivatives`。切换逻辑与报告域 `chooseConverterMode` 一致；也可以用 `VISUAL_DERIVATIVES=ci|script` 显式指定。
- **20 MB 上限**：数据万象持久化处理只接 20 MB 以内的图。超过的原图照样保存，`derivative_status=FAILED`，卡片与舞台显示「预览生成失败 · 可以查看原图」。以后需要时可以用脚本补生成。
- **兜底**：列表／详情接口遇到 `PENDING` 超过 60 秒的图片，就顺手再提交一次，思路同报告域"卡在 PROCESSING 超过 15 秒就顺手查一次"。
- **没生成好时显示什么**：卡片封面和舞台都显示深色占位加「正在生成预览」，**不拿原图顶替**（原图可能有几十 MB，HEIC 浏览器还打不开）。
- 派生图按 EXIF 方向转正，不带 EXIF；原图原样保存。

### 3.6 编辑权

| 动作 | 谁能做 |
|---|---|
| 上传 | 任何已登录成员 |
| 改标题／说明／标签／元数据／正文 | **原上传者**；系统管理员也可以处理 |
| 增删素材、调整顺序（含设为封面） | 原上传者；系统管理员 |
| 继续上传（补传或去掉没传完的素材） | 原上传者；系统管理员 |
| 删除 | 原上传者与系统管理员。**移入回收站，保留 90 天，可以恢复；原始素材文件不清理**（同视频、报告） |
| 查看 | 全员（仅限公司内部） |

没有权限的人**看不到按钮**（同报告卡片的 `canManage`、只读成果页的 `canTrash`），接口返回 403。所有写操作都走 `requireSameOriginMutation` 同源校验。

### 3.7 交互能力（本轮）

- **收藏：不限数量的纯收藏**。任何已登录成员都能收藏或取消，不设每周配额、不设票位、不跨周重置、不做排行奖励。同一人对同一条案例只有一次收藏，再点一次就是取消。独立表 `visual_case_favorites`，只记谁在什么时候收藏了哪条。
  - 与两个库的区别要写清楚：视频库、报告库的"每周三票"是为评选活动设计的配额投票，本域**不参与评选**，所以不照搬那套语义。收藏数只表示"有多少人觉得值得留档"，供「按收藏排序」使用。
  - **交互与视频库、报告库的心形完全一致**：同一个心形按钮（SVG 描边与实心切换）；点下去心形立刻翻面、计数立刻加减；同一张卡片的请求没回来之前不重复发；以服务端返回的计数为准；失败时退回原状并弹 warn 浮层。**成功不弹提示**，站里的收藏成功从来不弹。
  - 收藏数在查询时 `COUNT` 出来，**不存计数列**，所以"取消收藏必须把计数减回去"自然成立。
  - **「只看我收藏的」**（决定 #14）：库首页的一个开关。没有它，收藏过的东西就找不回来了。
  - **「按收藏排序」**：打开的那一刻冻结名次，之后点心形只改数字，不挪卡片；名次变了就出现「顺序已变 · 重新排序」，由用户决定要不要重排。做法同视频库的「按周显示」。
  - 还没上传完的案例不能收藏（按钮禁用，同报告库里未就绪的报告）。
- **评论**：**本轮不做**。视频和报告的评论都锚定"某个版本的某一条目"；公共视觉没有条目、没有版本，照搬过来会得到一条没处挂的评论。要做时单独设计锚点（针对案例整体、某张图或某段正文），不在本轮。
- **评分／星级**：不做（没有作业，就没有可评分的对象）。

### 3.8 规模与配额

- 单段视频、单张图片不设业务层面的体积上限（同 `README.md` 现有口径）；底层保留安全与稳定性保护。超过 20 MB 的图片不生成预览，见 3.5。
- 单案例上限：视频 12 段、图片 24 张，合计不超过 36 份；正文不超过 20000 字。
- 列表一次读全量，在前端筛选、搜索、排序（同视频库、报告库），不分页；条目过千再议。

### 3.9 外观：深色／浅色／跟随系统

1. **不新造主题机制**，沿用 `lib/theme.ts` + `components/shared/ThemeSwitcher.tsx` + `ThemeProvider`（偏好存 cookie `hm-theme`，默认深色）。样式里的颜色**只写 `var(--v04-*)`**，写死的色值会被 `tests/theme.test.ts` 拦下，深色岛除外。
2. **本域只新增一组变量**：`--v04-visual-ooh` ／ `--v04-visual-art` ／ `--v04-visual-retail`，以及各自的 `-rgb`（给半透明描边用）。深浅两套都要给值，浅色那组在 `app/globals.css` 里写两遍（手动浅色、跟随系统），必须逐字一致。取值见 demo 顶部；浅色下三者对纸底的对比度都 ≥4.5:1。
3. **深色岛**：卡片封面、详情页的舞台与素材条、对话框里的素材格、大图查看的图区，全部加 `data-v04-scheme="dark"`，两种主题下都是深色，同视频封面、报告页图。**封面占位不再按主题分两套**，V0.1 的"浅色下用更浅的渐变"作废：封面是照片，照片本来就不随主题变。
4. **先行提交**：把全站 `--v04-faint` 调高到 `#8b8e83`（深）／`#6d6e67`（浅），对比度从 3.75／3.47 提到 5.68／4.52。本域的小字灰依赖它。这一步作为实现的第一个提交单独合入，改完后在视频库、报告库深浅两套下各抓一遍计算色做 diff，确认只有这一处变化。

## 四、数据架构

### 4.1 原则

- 独立表族，不挂 V0.4 契约，不建版本链，不建评审表。
- 派生值不入库：封面（第一位素材）、载体摘要、素材计数、收藏数都在查询时推导。
- 软删除统一用 `deleted_at`，与视频、报告一致。

### 4.2 新表

```sql
-- 案例主表（字段命名与软删除约定对齐 videos / reports）
CREATE TABLE IF NOT EXISTS visual_cases (
  id TEXT PRIMARY KEY,
  domain_key TEXT NOT NULL DEFAULT 'PUBLIC_VISUAL',
  subdomain TEXT NOT NULL,                       -- OOH | PUBLIC_ART | RETAIL
  title TEXT NOT NULL,
  summary TEXT NOT NULL DEFAULT '',              -- 一句话摘要，≤60 字
  text_body TEXT NOT NULL DEFAULT '',            -- 正文（纯文本，保留换行）
  tags_json TEXT NOT NULL DEFAULT '[]',
  location TEXT NOT NULL,                        -- 采集地点，必填
  creator TEXT NOT NULL DEFAULT '',              -- 创作方／品牌
  occurred_at TEXT NOT NULL DEFAULT '',          -- 首次投放／落成时间，原文保存不解析
  source_url TEXT NOT NULL DEFAULT '',           -- 只收 http(s)
  rights_note TEXT NOT NULL DEFAULT '仅公司内部学习使用',
  metadata_json TEXT NOT NULL DEFAULT '{}',      -- 子领域专有项，见 3.3.2
  metadata_schema_version TEXT NOT NULL DEFAULT 'visual-metadata/1',
  status TEXT NOT NULL DEFAULT 'UPLOADING',      -- UPLOADING | READY（见下方「状态」）
  created_by_email TEXT NOT NULL,
  created_by_name TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TEXT
)
```

```sql
-- 素材：视频和图片排在同一条序列里，position 就是展示顺序，第一位就是封面。
-- 视频 ≤12、图片 ≤24 的约束放在服务层校验，不用部分唯一索引：
-- 约束将来可能放宽，写死在 DB 层就得迁移才能改。
CREATE TABLE IF NOT EXISTS visual_case_assets (
  id TEXT PRIMARY KEY,
  case_id TEXT NOT NULL REFERENCES visual_cases(id),
  type TEXT NOT NULL,                            -- VIDEO | IMAGE
  position INTEGER NOT NULL,                     -- 0 起；调整顺序时在一个事务里整体重写
  object_key TEXT NOT NULL,                      -- 原始素材
  thumbnail_key TEXT,                            -- 图片：480w 派生图；视频：浏览器截帧封面（≤1600w）
  display_key TEXT,                              -- 图片：1600w 派生图；视频为空
  original_name TEXT NOT NULL DEFAULT '',
  content_type TEXT NOT NULL DEFAULT 'application/octet-stream',
  file_size INTEGER NOT NULL DEFAULT 0,
  width INTEGER NOT NULL DEFAULT 0,
  height INTEGER NOT NULL DEFAULT 0,
  duration_seconds INTEGER NOT NULL DEFAULT 0,   -- 视频用
  upload_status TEXT NOT NULL DEFAULT 'UPLOADING',   -- UPLOADING | READY
  derivative_status TEXT NOT NULL DEFAULT 'PENDING', -- PENDING | READY | FAILED
  derivative_error TEXT,
  derivative_requested_at TIMESTAMPTZ,           -- 兜底重提交按它判断「PENDING 超过 60 秒」
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
)
```

```sql
-- 纯收藏，不限数量：主键就是 (case_id, user_id)，再点一次就是取消，不是再投一票。
-- 刻意不照抄 case_weekly_favorites / report_weekly_favorites：那两张表的 week_key 与 slot
-- 是评选活动的配额语义，本域不参与评选，带过来只会让人误以为这里也要每周限票。
CREATE TABLE IF NOT EXISTS visual_case_favorites (
  case_id TEXT NOT NULL REFERENCES visual_cases(id),
  user_id TEXT NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (case_id, user_id)
)
```

索引：`visual_cases (created_at DESC) WHERE deleted_at IS NULL`、`visual_cases (subdomain, created_at DESC)`、`visual_case_assets (case_id, position)`、`visual_case_favorites (user_id)`（算"我收藏了哪些"）。

**状态**：

- 建条目时：有素材的案例和它的每个素材都是 `UPLOADING`；只有正文的案例直接是 `READY`。
- complete：逐个 `head()` 核对素材，到位的置 `READY`。全部到位时案例置 `READY`，并提交派生图；有缺的就返回缺失清单（409），案例保持 `UPLOADING`。
- `UPLOADING` 的案例：库里所有人都能看到一张「上传未完成」的卡片（同报告库未就绪的卡片）。只有上传者和系统管理员能「继续上传」（重传缺的，或者去掉缺的、其余入库）和删除；其他人点了只得到一句浮层提示。
- 已经 `READY` 的案例追加素材时，案例保持 `READY`；新素材传完之前不上舞台，也不计入载体摘要。详情页给有编辑权的人一个「有 N 个新素材没传完 · 继续上传」的入口。

**RLS**：三张表都必须加进 `db/bootstrap.ts` 末尾的 RLS 清单，否则 Supabase 会把它们设成公开可读，`tests/schema-rls.test.mjs` 也会报红（`web/README.md` 已经用一次事故写过这条）。

**迁移**：新增 `db/migrations/<实施当天>-public-visual.sql`，只加不改，可重复执行；`db/bootstrap.ts` 同步作为唯一的 schema 来源。**先迁移，再部署**，不得在 build／start／deploy 时自动执行。

### 4.3 对象存储键

```
visual/{caseId}/{assetId}/original.{ext}   原始素材（视频或图片，预签名直传）
visual/{caseId}/{assetId}/cover.jpg        视频截帧封面（≤1600w，浏览器生成）
visual/{caseId}/{assetId}/thumb.jpg        图片 ≈480w 派生图
visual/{caseId}/{assetId}/display.jpg      图片 ≈1600w 派生图
```

沿用 `getVideoBucket()`（本机为 `LocalVideoBucket`，线上为 COS）。要不要顺手改名成 `getObjectBucket()` 不强求。

## 五、接口

命名与 `app/api/videos/*`、`app/api/reports/*` 平行。鉴权一律 `requireApiUser`，写操作加 `requireSameOriginMutation`。服务层放在 `lib/visual-*.ts`；纯函数（元数据校验、标签归一、载体摘要、封面取舍、顺序重写）放在 `lib/visual-metadata.ts` 与 `lib/visual-model.ts`，**这一层要有单测**。

| 方法与路径 | 作用 |
|---|---|
| `POST /api/visual-cases` | 建条目。body：`subdomain`、`title`、`location`、`tags`、`textBody?`、`summary?`、`creator?`、`occurredAt?`、`sourceUrl?`、`rightsNote?`、`metadata`，以及按展示顺序排好的 `assets: [{ type, originalName, contentType, fileSize, durationSeconds?, width?, height? }]`。返回 `caseId` 和每个素材的 `assetId`，**不在这里签上传链接** |
| `POST /api/visual-cases/[id]/assets/[assetId]/upload-url` | 为单个素材签发 PUT 链接（600 秒；视频另外带一个封面 PUT）。前端**用到哪个签哪个**，同时传 3 个。理由：COS 签名最长 900 秒，一次签 36 个的话，排在后面的视频轮到上传时链接早就过期了 |
| `POST /api/visual-cases/[id]/complete` | 逐个 `head()` 核对（视频沿用视频域的 `file_size` 一致性校验），返回 `{ status, missing: [assetId…] }`；有缺的返回 409。只有上传者和系统管理员能调 |
| `GET /api/visual-cases` | 全量列表（前端筛选、排序）。每条带：载体计数、封面素材的缩略图签名 URL 与 `derivative_status`、`favoriteCount`、`viewerFavorited`、`canManage`、`status` |
| `GET /api/visual-cases/[id]` | 详情：元数据 + 已传完素材（缩略图与展示图的签名 URL，**不签原图**）+ 正文 + 收藏状态 + `viewerCapabilities { canEdit, canTrash }` + 没传完的素材数（仅在 `canEdit` 时返回） |
| `GET /api/visual-cases/[id]/assets/[assetId]/original` | 点「查看原图」时才签原图 GET；HEIC 带 `Content-Disposition: attachment` |
| `PATCH /api/visual-cases/[id]` | 改元数据、正文、素材顺序（`assetOrder: [assetId…]`，在一个事务里整体重写 `position`，**不按类型重排**）；带 `updated_at` 乐观锁，对不上就返回 409 |
| `POST /api/visual-cases/[id]/assets` ／ `DELETE …/assets/[assetId]` | 追加素材（返回 `assetId`，再走 upload-url 与 complete）；移除素材（同时删对象和派生图） |
| `POST /api/visual-cases/[id]/favorite` | 收藏或取消，形状同视频库、报告库的 `POST …/favorite`（返回 `favorited`、`favoriteCount`）；没有配额分支 |
| `POST /api/visual-cases/[id]/trash` ／ `restore` | 移入回收站／恢复（同视频域） |

写入校验（都返回 400 和可读的中文原因）：必填项与长度（3.3.1）、`subdomain` 词表、`metadata` 未知键（报出键名）、单选值不在选项里、多选不是数组、`sourceUrl` 不是 http(s)、图片格式不在白名单、素材数量超限。

**刻意没有的接口**：任何 `annotation`、`versions`、`review`、`release` 路径。

- **大图查看**（只看图片）：`.ov` 外框；眉头写「图片 02 / 05」，加标题、「← 上一张」「下一张 →」「查看原图」「关闭 esc」。Esc 关闭，←→ 翻页，**到首尾不回绕**（同报告工作台的页面 modal）；打开时锁住 body 滚动；点遮罩关闭。**键盘监听全页只挂一次**，按当前浮层分派。
- **正文**（`readingModule`「TEXT / 正文」）：纯文本，保留换行，**按文本插入**，不走 `innerHTML`，也不解析任何标记。
- **案例信息**（`readingModule` + `readingCore` 两栏，窄屏一栏）：通用项加该子领域的专有项；空字段不渲染；多选用「、」连接；来源链接可点击。
- **删除**：用 `DeleteConfirmDialog`，正文两行："案例会从公共视觉库中移除，保留 90 天，可由上传者或系统管理员恢复；原始素材文件不会被清理。""收藏关系一并保留，恢复后原样回来。" 默认焦点在「取消」上；提交中不能关。成功后回到库首页，不弹提示（同只读成果页）。

### 6.4 上传／编辑对话框

- **外壳**：`ReportUploadDialog` 那一套（560 宽，眉题 `UPLOAD`／`EDIT`，右上角 ×）。表单比报告上传长，所以页头和底部按钮栏分别吸顶、吸底。
- **字段顺序**：
  1. 选文件，放在第一位（同两个上传对话框），可以多选；
  2. 素材格：一条混排列表，第一位标「01 · 封面」；每格有 ⤒ 设为封面、← →、×；上方计数写「视频 n / 12 · 图片 n / 24」；超过 20 MB 的图片标出体积；
  3. 子领域（下拉）；
  4. 标题；
  5. 采集地点 ｜ 标签；
  6. 正文；
  7. 「补充信息（选填）」折叠区：创作方、时间、摘要、来源链接、版权说明、子领域专有信息。折叠按钮上写着"含户外广告专有 4 项，已填 n"。
- 在手机宽度下，收起补充信息时，整张表单一屏放得下（V0.1 要 4 屏）。
- **校验**：按「子领域 → 标题 → 地点 → 标签 → 至少一种载体 → 来源链接格式」的顺序依次拦，报错写在 `formError`（`role=alert`）里；提交按钮不预先禁用。
- **关闭规则**：× 和「取消」随时可以关。**点遮罩和按 Esc，只在表单还是空的时候才关**：这张表单比报告上传长得多，误点一下全丢了不划算；视频上传对话框本来也不响应遮罩。上传过程中不给关，按报告上传的做法，直接不渲染 ×。
- **上传中**：整张表单换成进度块（「第 n / N 个 · 文件名 · 百分比 · 进度条」），逐个直传。
- **部分失败**：不把整条案例判为失败，而是进入「有 N 个文件没传上」这一步，列出文件，给三个选择：
  - 「重传这 N 个」：只补缺的；
  - 「去掉它们，其余入库」；
  - 「稍后再说」：关掉对话框，卡片显示上传未完成，之后可以从卡片上的「继续上传」回到这一步。
  - 去掉之后如果既没有素材也没有正文，就拦下。
- **成功**：关掉对话框，刷新列表，新卡片排在最前（显示「正在生成预览」），弹一句「已上传，预览生成后自动出现」；如果新卡片被当前筛选挡住了，就清掉筛选。在详情页里编辑保存后留在详情页，弹「已保存」。
- **编辑**：用同一个对话框，内容预填，补充信息默认展开。素材格里包括已有素材，上次没传完的标「没传完」。保存时按对话框里的顺序整体写回 `position`。换子领域时丢掉旧子领域的专有字段。

### 6.5 开关与上线

| 开关 | 作用 | 默认 |
|---|---|---|
| `PUBLIC_VISUAL_LIBRARY_ENABLED` | 公共视觉库总开关。关闭时接口一律 404；页签按钮在，但按不动（它说明的是形状，不是承诺，同报告库的处理） | 关闭 |
| `VISUAL_DERIVATIVES` | `ci`／`script`，不设时按 3.5 的规则自动选 | 不设 |

上线顺序照既有约定：**`--v04-faint` 先行提交 → 迁移 → 部署代码 → 打开开关**。开关不进 `vercel.json` 的常驻清单，功能自验通过后再单独追加，并且保留随时关掉的能力。

## 七、验收标准

1. 四类案例各上传一次：**多视频（≥2 段）**、**纯图片（≥3 张，无视频无正文）**、纯文字、混合（视频 + 图片 + 文字）。在库里都能看到卡片，载体摘要与封面正确；混合案例的详情页上，舞台、正文、案例信息三块都在。
2. 封面就是第一位素材：视频排第一时卡片有播放圆和时长，图片排第一时没有；在对话框里对任意一格点「设为封面」，保存后卡片封面随之改变。
3. 详情页：素材条按 `position` 列出全部素材；点第 3 格，舞台切到第 3 个，时钟显示这一段自己的时长；纯图片案例首屏就是第一张图，纯文字案例没有舞台。
4. 编辑一个"图片在前、视频在后"的案例并保存，顺序不变（服务端按 `assetOrder` 写回，不按类型重排）。
5. 三个子领域各上传一次，专有字段随子领域切换；从户外广告切到商业展陈后保存，`metadata_json` 里没有户外广告的键；直接调接口带未知键返回 400；多选存的是数组。
6. 缺子领域、缺标题、缺地点、缺标签、没有任何载体、来源链接是 `javascript:`，都会按顺序被拦下，并给出可读的提示。
7. 一次提交 25 张图片、13 段视频都会被拒；每个素材的上传链接都是用到时才签发，最后一个视频开始上传时链接没有过期。
8. 部分失败：模拟 1 个文件没传上，对话框进入「有 1 个文件没传上」；「重传」只补这一个；「稍后再说」之后卡片显示「上传未完成」，只有上传者和管理员能看到「继续上传」「删除」。
9. 图片：卡片用 480w、舞台用 1600w、原图只在点「查看原图」时签名，三者的 object key 不混用；HEIC 能生成 JPG 预览，查看原图时以附件下载；超过 20 MB 的图片显示「预览生成失败 · 可以查看原图」；派生图没生成好时显示占位，而不是原图。
10. 收藏不限数量：连续收藏 10 条全部生效；同一条再点一次就取消，计数回落；刷新后状态与计数不变；「只看我收藏的」只剩这 10 条；「按收藏排序」打开后点心形，卡片不挪位，并出现「顺序已变 · 重新排序」；成功时不弹提示。
11. 权限：非上传者看不到编辑、删除、继续上传的按钮，直接调接口返回 403；系统管理员可以处理。删除后进入回收站、可以恢复，恢复后素材与收藏关系都还在。
12. **与全站一致**：卡片、上传对话框、删除确认、浮层提示、外观开关，与视频库、报告库逐项对比计算样式（字号、边框、圆角、颜色）一致；在深浅两套主题下都没有写死的颜色（`tests/theme.test.ts` 通过），深色岛在浅色主题下仍是深色。
13. **视频库与报告库回归**：加页签之后，视频库的卡片、搜索、按周显示，报告库的四种状态与工作台入口，逐项不受影响；`--v04-faint` 先行提交之后，深浅两套主题的计算色 diff 只有这一处变化；`npm run lint`、`npx tsc --noEmit`、`npm test` 全部通过。
14. 正文里输入 `<img src=x onerror=…>`，页面上原样显示成文字，不执行。
15. `lib/visual-*.ts` 单测覆盖：三个子领域的必填与专有字段校验、未知键拒绝与旧键保留、标签归一与去重、来源链接协议校验、载体摘要（多视频／纯图片／纯文字）、封面取舍（第一位素材）、顺序整体重写、乐观锁冲突。

## 八、明确不做（本轮）

1. **不做逆向拆解**：无标注字段、无 9＋10、无组块、无结构划分。
2. **不做标准版本与专业域登记**：不建 `taxonomy_version`，不登记 `professional_domains`，不进 V0.4 契约。
3. **不做版本链**：一条案例一份内容，改了就是改了，不留历史版本，不做集成版／最终版。
4. **不做评审与作业**：无百分制、无互评轮次、无晋级、无作业分发。
5. **不做评分／星级**（没有可评分的作业对象）。
6. **不做评论**（锚点未定，见 3.7）。
7. **不做 AI 辅助**（与两个库的既有搁置一致）。
8. **不做批量建案例与去重**：一次建一条案例（一条案例可以一次选多个文件）；相似案例检测、重复素材提示不做。
9. **不做标签条**：标签靠搜索（同视频库、报告库）。
10. **不做对外公开分享**（见 2.4）。
11. **不改视频域与报告域的任何既有行为**，只有 6.1 所说的一个页签分支，以及 3.9 第 4 条的 `--v04-faint` 调整。

### 9.5 V0.1 demo 的缺陷与这一版的处理（实现时不要重犯）

| V0.1 的问题 | 这一版 |
|---|---|
| 页签、返回链接、提示文案写成"视觉库" | 统一为「公共视觉库」 |
| 公共艺术的子领域色没生效（`tone:"s-art"` 对不上 `.s-PUBLIC_ART`）；商业展陈能显示颜色，是因为文件缺 doctype、跑在兼容模式下类名不分大小写 | 补 doctype；子领域色走 `data-sub` + `--v04-visual-*` 变量 |
| 纯文字封面写成 `background:[object Object]`，两套主题下都是黑块 | 深底标题排版，属于深色岛 |
| 多视频角标只写"视频"，不带数量 | 载体摘要统一带数量 |
| 切到第 2 段视频后，时钟仍显示第 1 段的时长 | 时钟跟着当前段 |
| 纯图片／纯文字案例打开详情时报错 | 没有视频就不渲染播放控件，也不绑定 |
| 大图的键盘监听每开一次叠一个，开关两次后按一下跳三张 | 全页只挂一个键盘监听，按当前浮层分派；到首尾不回绕 |
| 「设为封面」提交时被忽略 | 设为封面就是挪到第一位，只有一条规则 |
| 多选在示例数据里显示成一个"体感,声音"药丸，编辑时选中状态丢失 | 多选一律存数组 |
| 换子领域后，旧子领域的键残留 | 换子领域时丢掉整组；服务端拒绝未知键 |
| 正文用 `innerHTML` 插入，可以执行脚本 | 按文本插入 |
| 编辑时版权说明不回显，也不保存 | 回显并保存 |
| 别人上传的案例也显示编辑、删除 | 按权限渲染；demo 右上角可以切换身份看效果 |
| 手机上表单 4 屏高；点遮罩就丢掉整张表单 | 选填项折叠后一屏；有内容时不响应遮罩和 Esc |
| 收藏成功弹提示；页首有一条"收藏不限票数"横幅；有一排标签条 | 同全站：收藏成功不弹；说明放进按钮的 title；标签走搜索 |

demo 自身还有一处要说明：内置浏览器把本地文件当 `data:` 地址打开，这时不允许改地址栏，也读不了 localStorage。所以 demo 的路由记在内存里，只用 `pushState` 同步地址栏（改不了就算了），外观偏好读写也都包了 try/catch。线上是真正的路由和 cookie，不受影响。
