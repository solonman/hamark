# 逐镜编辑自动保存防卡顿设计

## 目标

减少逐镜脚本编辑时的数据库写入和全表保存竞争，使连续输入保持流畅，同时不丢失草稿、不改变发布流程。

## 保持不变

- 每个用户仍只能保存自己的作业草稿，既有鉴权、修订冲突和发布校验不变。
- 点击“发布作业”仍在提交前立即保存当前最新内容。
- 自动保存失败仍显示错误，不把失败状态伪装成已保存。
- 编辑过程中后一次内容不能被较早保存请求的响应覆盖。

## 方案

把作业页的尾随自动保存延迟从 900 毫秒调整为 2.5 秒。每次编辑都会重置计时器；只有用户停止编辑约 3 秒后才提交一次完整草稿。保存正在进行时产生的新编辑保留为脏状态，当前保存完成后再按相同延迟保存最新草稿。

保存成功时，以编辑序列号判断响应是否仍对应当前内容：若期间有新增编辑，只更新服务端给出的草稿标识、修订号和时间，不清除脏状态，也不以旧请求体替换用户正在输入的字段。

顶部状态提示改为“修改约3秒自动保存”，使产品反馈与实际节流策略一致。

## 验证

- 单元/源码测试锁定 2500 毫秒延迟和顶部状态文案。
- 测试保存响应在有较新编辑时不清除脏状态。
- 完整运行 lint、生产构建和所有测试。
- 手工输入长文本、连续停顿输入和保存期间继续输入，确认不会逐字符请求、不会卡顿或丢字；点击发布时确认立即保存。
