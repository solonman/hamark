# 直连 COS 视频播放设计

## 目标

将已登录用户的视频播放流量从 Vercel 函数中转改为浏览器直连上海 COS，缩短作品详情打开后的首帧等待，同时保持现有的内部访问权限与不提供下载入口的产品行为。

## 不变条件

- 未登录用户仍不能读取视频详情或取得播放地址。
- 仅 `READY` 且未进入回收站的视频可播放。
- 原有视频详情、练习和分析 URL 及其字段保持不变。
- 页面仍使用内嵌播放器；页面不增加下载按钮或原片下载接口。
- 视频列表的排序、状态文案和卡片跳转不改变。

## 方案选择

详情接口在现有鉴权和数据库读取成功后，为 `READY` 视频生成带签名的 COS 只读播放 URL，过期时间为三小时。前端详情页将该 URL 作为 video 元素的 `src`；COS 负责媒体 Range 请求和字节传输，Vercel 不再读取或回传视频内容。

保留 `/api/videos/:id/stream` 作为兼容端点，但详情页与列表页不再使用它。这样可避免改变既有外部链接或一次性移除端点带来的风险。

列表卡片移除 `preload="metadata"` 的视频流请求，改为静态占位视觉，防止列表一打开就为所有影片并发创建鉴权、数据库和 COS 请求。

## 接口和数据流

`GET /api/videos/:id` 的 `video` 对象增加可选字段 `playbackUrl`：

- `READY`：一个对该对象有效、三小时后过期的 COS GET 签名 URL；
- 其他状态：`null`。

COS 客户端新增生成 GET 预签名 URL 的能力。签名包含对象路径与有效期，但不暴露 COS 密钥。链接使用 `response-content-disposition=inline`（若 COS 支持对应响应覆盖）或对象既有内嵌内容类型；这表达站内播放意图，但不宣称能阻止浏览器保存媒体。

详情页在取得视频详情后直接把 `playbackUrl` 传给播放器。替换原视频后，页面刷新详情数据而非只修改本地状态，确保得到新对象的播放签名。若签名过期或播放器出错，展示明确的“播放链接已失效，请刷新页面”提示，而不静默中转回 Vercel。

## 验证

- COS 签名单元测试验证方法为 GET、路径编码、三小时有效期和不含下载参数。
- 详情接口测试验证：未登录仍返回 401；READY 视频返回播放 URL；非 READY 视频不返回 URL。
- 页面源码测试验证：详情播放器消费 `playbackUrl`，列表不再请求 `/stream` 或设置 `preload="metadata"`。
- 完整运行 lint、现有测试与生产构建；部署后以登录账号确认详情秒开、播放 Range 请求直接命中 COS 域名。
