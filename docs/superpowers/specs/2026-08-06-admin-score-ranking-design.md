# 管理员评分排行弹层设计

## 目标

在首页顶部为管理员提供起止日期与“查看评分”入口。查询结果以弹层展示，不离开首页；管理员可在新标签页打开任意排名作品的详情页。

## 权限与管理员数据

- 新增 `app_admins` 表，字段为 `display_name`（主键）、`created_at`；由数据库初始化脚本预置“老孙”“李丽萍”“晏恩华”。
- 权限判断只在服务端执行：当前企业微信会话中的 `CurrentUser.displayName` 与 `app_admins.display_name` 精确匹配时为管理员。
- 非管理员不接收首页评分入口；即使直接请求排行接口，接口也返回 403。
- 本期按显示姓名授权是业务确认的选择；将来若需避免同名，可把表改为保存 `identity_key`，不改变接口与页面职责。

## 页面与交互

- 管理员首页头部、搜索框左侧展示两个原生日期输入框与“查看评分”按钮。
- 未填完整日期或起始日期晚于结束日期时，不发请求并显示就地错误。
- 点击按钮后调用仅管理员可用的排行接口；请求期间按钮显示加载状态。
- 成功后打开居中弹层，背景遮罩并禁止背景交互；关闭按钮、点击遮罩、Esc 均可关闭弹层。关闭后保留首页搜索、滚动位置和已选日期。
- 弹层显示日期范围、作品数量与按分数降序排列的列表。每行显示排名、片名、品牌、有效评分作业数和平均分；没有符合条件的数据时显示空状态。
- 每个排行行是链接，使用 `target="_blank"` 与 `rel="noopener noreferrer"` 打开 `/videos/:id`，原首页和弹层不发生跳转或关闭。

## 排行数据与边界

- 日期范围按视频上传时间 `videos.created_at` 过滤，起止日均包含；服务端将结束日解释为下一自然日之前，从而包含结束日全天。
- 仅统计未删除视频，以及关联到该视频的 `assignment_reviews` 中 `status = 'SUBMITTED'`、`is_valid_for_aggregate = 1`、`deleted_at IS NULL` 的评分。
- 视频总分为其所有有效已提交评分的 `AVG(total_score)`；有效评分数为对应 `COUNT(*)`。
- 没有有效评分的视频不出现在结果中。排序为平均分降序、有效评分数降序、视频上传时间降序，保证同分时结果稳定。
- 数据由专用 `GET /api/admin/video-score-ranking?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 返回；响应仅含弹层所需字段。

## 代码边界

- `web/lib/admin.ts`：管理员常量/服务端校验帮助函数，不暴露数据库权限规则给客户端。
- `web/app/api/admin/video-score-ranking/route.ts`：会话、管理员与日期参数校验，以及聚合查询。
- `web/app/components/ScoreRankingDialog.tsx`：弹层、无障碍焦点/关闭处理与新标签页链接。
- `web/app/components/HomeClient.tsx`：仅承载管理员入口状态与请求结果；`web/app/page.tsx` 传入服务端算出的 `isAdmin`，避免普通用户先渲染入口。
- `web/db/supabase.sql` 与 `web/db/bootstrap.ts`：建表及管理员种子数据。

## 测试

- 管理员判断：三个预置姓名通过，非管理员拒绝。
- 排行接口：401 未登录、403 非管理员、400 日期缺失/倒置、跨日边界包含结束日、过滤无效/草稿/删除评分、稳定排序。
- 首页组件：非管理员不显示入口；管理员能打开、关闭弹层；排行榜链接包含新标签页安全属性。
