# 视频信息编辑与永久删除

## 目标

让视频原上传者能在作品详情页维护作品元数据，并在未产生任何已提交作业时永久删除错误上传的视频。保留现有的原视频替换能力。

## 范围

### 上传者操作区

详情页仅对原上传者显示一个“管理作品”入口。入口展开后提供：

- 编辑信息
- 替换原视频（沿用已有流程）
- 永久删除（危险操作）

非上传者看不到这些操作；服务端仍独立校验所有权。

### 编辑信息

编辑弹窗预填当前标题、品牌、标签和说明。保存时调用视频详情的 `PATCH` 接口，只更新这四个元数据字段及 `updated_at`。它不更换视频文件、封面或播放链接，也不修改作业、分析和评分。

标签沿用上传时以中英文逗号分隔、去除空白的规则。保存成功后客户端用接口返回的元数据更新当前页面；失败时弹窗保留输入并显示错误。

### 永久删除

永久删除只在没有任何已提交作业时可用。判定条件是该视频不存在已提交的分析快照（`annotation_snapshots`）；草稿不会阻止删除。

删除按钮打开二次确认弹窗，明确说明原视频、封面和数据库记录将永久删除且无法恢复。确认请求使用 `DELETE /api/videos/:id`。服务端在同一删除路径中重新检查：

1. 当前用户是原上传者；
2. 视频仍存在；
3. 不存在已提交作业。

通过检查后，删除 COS 中的视频与封面对象，清理与该视频关联的草稿和其他关联记录，最后删除视频记录并写入审计日志。对象删除失败时不删除数据库记录，以便用户重试且避免留下损坏的详情链接。成功后客户端跳转片库。

如果在打开确认弹窗后有人提交了作业，服务端返回冲突错误；页面关闭弹窗并提示“已有作业提交，无法删除视频”。

## 数据与接口

- `GET /api/videos/:id` 新增 `canManage` 与 `canDeletePermanently`：前者代表上传者；后者代表上传者且无已提交作业。
- `PATCH /api/videos/:id` 接受 `title`、`brand`、`tags`、`description`，只允许上传者修改。
- `DELETE /api/videos/:id` 从现有软删除改为带关联清理的永久删除，并阻止存在 `annotation_snapshots` 的视频删除。

## UI 与错误处理

管理菜单保持详情页现有克制的胶囊按钮样式；删除入口使用红色文字与边框。编辑和删除分别使用独立、带焦点语义的对话框。所有请求处理中禁用相应按钮，网络和权限错误在对话框内展示。

## 测试

- 接口源代码/行为测试覆盖 PATCH 的上传者权限与字段更新约束。
- DELETE 测试覆盖：非上传者拒绝、有提交作业时拒绝、无提交作业时执行永久删除路径。
- 客户端测试确认管理入口、编辑对话框和删除确认流程仅在相应权限/状态下出现。
