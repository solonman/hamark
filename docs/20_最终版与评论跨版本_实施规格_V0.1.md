## 一、冻结的产品规则

### A. 评论跨版本展示（权限不变）

1. **写的权限不变**：仍只有老孙（`lib/case-review.ts` 的 `CASE_REVIEWER_NAME`）能写，服务端 `requireReviewer` 照旧。一版一个条目一条，写下去锚定**当前正在看的版本**（含最终版）。
2. **展示跨版本**：不管看哪一版，条目的评论气泡都汇总显示该条目在**所有版本**上的评论，每条标出写在哪一版（`v2` / `最终版`），属于当前版本的那条高亮标“本版”。
3. 老孙看到写在别版上的评论时显示“切到该版可改”，不能在当前版本上改别版的那条；要改就切过去改。其他人所有评论只读。
4. 没有任何版本评论过的条目，非老孙看不到 💬 入口（与现状一致）。固定选项条目仍无评论入口。
5. **最终版不评分**：星级仍只锚定个人版本。最终版页面不渲染评分组件。

### B. 最终版

6. **定义**：每个案例（工作区）有且只有一个「最终版」，版本菜单置顶显示。它不属于任何人，内容按处取最新：任一普通版本改了哪一处，最终版的那一处就换成谁的，**后改覆盖先改**。插入／删除桥段和镜头同样汇入。
7. **两态**：`OPEN`（进行中）自动汇入；`DONE`（已定稿）时其他版本的修改不进最终版，只记为“未纳入”。只有老孙能「定稿」「取消定稿」。
8. **取消定稿后**，定稿期间产生的“未纳入”修改**不自动补进**，由老孙在溯源视图里逐条「采纳」或横幅上「全部采纳」。采纳按产生顺序落到最终版上。
9. **只有老孙能直接编辑最终版**。其他人在最终版页面点内容会被拦下并提示「最终版只有老孙可以编辑」，不会为他创建版本。老孙直接改的记为“直接修改”，也进入溯源链；进行态下若之后有普通版本改同一处，照样被覆盖（规则 6）。老孙自己的普通版本照旧存在：他在别人版本上编辑仍创建／回到自己的版本。
10. **两种视图**：`默认` 只显示每处当前采用的内容，hover 标题可见来自哪一版；`溯源` 在每处内容下按更新顺序列出该处所有版本的写法，标 `原稿`／`已被覆盖`／`当前采用`／`未纳入`，未纳入项带「采纳这一版」按钮（仅老孙）。
11. **进入页面默认展示最终版**（案例已有真实版本时）。原“默认最新修改版本”规则退为：显式 `?version=` 指定时按指定；最终版尚不存在（案例还没有任何真实版本）时保持原行为。
12. 顶栏版本按钮在最终版时显示 `最终版` + 状态胶囊（进行中／已定稿）；最终版页面不显示「比较基版」。

## 二、数据

新增两张表，附加式：新增 `db/final-version-schema.ts`（导出 `FINAL_VERSION_SCHEMA_STATEMENTS`，接进 `db/bootstrap.ts`），并新增 `db/migrations/2026-09-02-final-version.sql` 供生产手工执行（写法与 `db/migrations/2026-09-01-case-engagement.sql` 一致：BEGIN/COMMIT、IF NOT EXISTS、RLS 收口、头部注释说明不要用 `db:migrate`）。

```sql
CREATE TABLE IF NOT EXISTS analysis_final_versions (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL UNIQUE REFERENCES collaboration_workspaces(id),
  video_id TEXT NOT NULL REFERENCES videos(id),
  status TEXT NOT NULL DEFAULT 'OPEN' CHECK (status IN ('OPEN', 'DONE')),
  done_at TIMESTAMPTZ,
  done_by_user_id TEXT REFERENCES users(id),
  done_by_name TEXT,
  origin_payload_json JSONB NOT NULL,   -- 创建时的起点，溯源里的「原稿」
  payload_json JSONB NOT NULL,
  content_hash TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 1 CHECK (revision > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 汇入记录：每一条都是「某处的一次修改」，溯源视图与“未纳入”都从这里读。
CREATE TABLE IF NOT EXISTS analysis_final_intakes (
  id TEXT PRIMARY KEY,
  final_id TEXT NOT NULL REFERENCES analysis_final_versions(id),
  workspace_id TEXT NOT NULL REFERENCES collaboration_workspaces(id),
  video_id TEXT NOT NULL REFERENCES videos(id),
  seq BIGSERIAL NOT NULL,                -- 产生顺序；采纳与溯源都按它排
  kind TEXT NOT NULL CHECK (kind IN ('FIELD', 'INSERT_GROUP', 'INSERT_SHOT', 'REMOVE_GROUP', 'REMOVE_SHOT')),
  target_key TEXT NOT NULL,              -- FIELD 用稳定字段键；结构类用 shotGroup:<id> / shot:<id>
  target_label TEXT NOT NULL DEFAULT '',
  value_json JSONB NOT NULL,             -- FIELD: 字段值；INSERT_*: {item, parentGroupId, afterId}；REMOVE_*: {}
  source TEXT NOT NULL CHECK (source IN ('VERSION', 'FINAL_DIRECT')),
  source_version_id TEXT REFERENCES analysis_versions(id),
  source_version_number INTEGER,
  actor_user_id TEXT NOT NULL REFERENCES users(id),
  actor_name TEXT NOT NULL,
  change_set_id TEXT,
  applied BOOLEAN NOT NULL,
  applied_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS analysis_final_intakes_final_seq_idx ON analysis_final_intakes (final_id, seq);
CREATE INDEX IF NOT EXISTS analysis_final_intakes_final_target_idx ON analysis_final_intakes (final_id, target_key);
```

DROP CONSTRAINT IF EXISTS analysis_version_comments_version_id_fkey`；bootstrap 里的建表语句同步去掉 `REFERENCES`），因为最终版的 id 不在 `analysis_versions` 里。服务端改为自行校验 version_id 属于该案例（普通版本或最终版）。主键 `(version_id, target_key)` 不变。评分表不动。

## 三、汇入算法（`lib/final-version.ts`，纯函数部分必须可单测）

### 3.1 变更集 → 汇入记录（`decomposeV19ChangesForFinal`）

普通版本每次保存的变更集（`V04Change[]`，见 `lib/v04-ui-model.ts` 的 `v04PayloadChanges`）有两类：

- 普通字段键（`facts.*`、`path.*`、`shotGroup:<id>.<field>`、`shot:<id>.<field>`）→ 一条 `FIELD` 记录，`value_json = afterValue`。
- `script.structure`（整份 `shotGroups` 的 before/after，`valueType = "STRUCTURE"`；**此时客户端不会再单独发镜头字段变更**）→ 必须拆解，不能整体替换最终版结构，否则会盖掉其他人写的镜头内容。拆解规则（按 id 对齐）：
  - before 有、after 无的桥段 → `REMOVE_GROUP`（`target_key = shotGroup:<id>`）；两边都有的桥段里 before 有、after 无的镜头 → `REMOVE_SHOT`。
  - after 有、before 无的桥段 → `INSERT_GROUP`，`value_json = { item: 该桥段完整对象（含镜头）, afterId: after 列表里它前一个桥段的 id 或 null }`；两边都有的桥段里新增的镜头 → `INSERT_SHOT`，`value_json = { item, parentGroupId, afterId: 同桥段内前一镜头 id 或 null }`。
  - 两边都有的桥段／镜头，逐字段比较（桥段：bridgeName、primaryCreativeRole、auxiliaryCreativeRole、keyCreativeDescription；镜头：`V04_UI_SHOT_FIELDS` 的全部字段），不同的每个字段一条 `FIELD` 记录。
  - `target_label` 用 `v04PayloadChanges` 里同样的中文标签；镜头字段用字段标签。
  - 顺序：先 REMOVE，再 INSERT（按 after 顺序），再 FIELD。

### 3.2 一条汇入记录落到 payload（`applyFinalIntake(payload, intake) → { payload, effect: "APPLIED" | "NOOP" }`）

- `FIELD`：定位目标（与 `lib/v04-domain.ts` 的 `locateTarget` 同一规则；可把它导出复用），目标不存在（例如镜头已被别人删除）→ `NOOP`。
- `INSERT_GROUP`：id 已存在 → `NOOP`；否则插到 `afterId` 之后（`afterId` 为 null 插最前；`afterId` 在最终版里找不到则追加到末尾）。
- `INSERT_SHOT`：镜头 id 已存在于任何桥段 → `NOOP`；父桥段不存在 → `NOOP`；否则按 `afterId` 同上规则插入父桥段。
- `REMOVE_*`：不存在 → `NOOP`；存在则删除。
- 任何结构变化后重排序号：桥段 `orderIndex = 下标`；镜头 `orderIndex = 全局累计下标`（与 `lib/v04-ui-model.ts` 第 330–340 行一致）。
- 落库前 `assertV04PayloadContract(after)`；不通过则该条记为 `NOOP`，**绝不能让别人的保存因为最终版失败**。
- `NOOP` 也算 `applied = true`（它已被处理，只是无处可落）。

### 3.3 最终版的创建与回填（`computeFinalFromHistory` 纯函数 + `ensureFinalVersion`）

- 起点 `origin = 该工作区 v1（version_number 最小）的当前 payload`。
- 回放该工作区**全部**带 `version_id` 的 `collaboration_revision_events`（所有版本，按 `created_at, id` 升序），每条事件按 3.1 拆解、按 3.2 应用，生成 `applied = true` 的汇入记录。v1 自己的事件重放是幂等的；这样做是为了把 v1 与 v2 对同一处的先后关系排对。
- 首次持久化的时机：`saveV19VersionChanges` 里（事务内、`resolveOrCreateActorVersion` 之后）。**GET 不落库**（`tests/v19-api-contract.test.ts` 有“GET never materializes”守卫）：读取时若最终版不存在，用同一纯函数在内存里算出虚拟最终版（`isVirtual: true`），`id` 为 `null`。
- 新案例：v1 物化时（`materializeV19FirstVersion`）不必同时建最终版；第一次保存后走上面的路径即可。

### 3.4 普通版本保存时的汇入（改 `saveV19VersionChanges`）

在写完修订事件之后、同一事务内：`ensureFinalVersion` → 拆解 `appliedChanges` → 若 `status = 'OPEN'` 逐条应用并写 `applied = true, applied_at = now`，更新最终版 `payload_json / content_hash / revision / updated_at`；若 `DONE` 只写记录 `applied = false`。保存结果 `V19SaveResult` 增加 `finalIntake: { merged: boolean; pending: number }`（`merged` 指本次进入了最终版；`pending` 是最终版当前未纳入总数），前端据此出 toast。幂等重放（同 `changeSetId`）不得重复写汇入记录：以 `change_set_id + source_version_id` 判重。

### 3.5 老孙直接编辑最终版（`saveFinalVersionDirect`）

- 入口：`PUT /api/videos/[id]/analysis/v19`，`basedOnVersionId === "final"`。非老孙 → `V04ServiceError("FORBIDDEN", "最终版只有老孙可以编辑。")`。
- 用 `applyV04ChangeSetLastWriteWins` 直接应用到最终版 payload（这里整份 `script.structure` 替换是对的，因为 before/after 都来自最终版自己），校验契约，更新行；同时按 3.1 拆解写汇入记录 `source = 'FINAL_DIRECT', applied = true, source_version_id = null`，供溯源显示“最终版·直接修改”。同样按 `change_set_id` 幂等。
- 返回与普通保存同形的 `V19SaveResult`（`versionId = 最终版 id, versionNumber = 0`）。

### 3.6 定稿／取消定稿／采纳

- `setFinalVersionStatus(db, actor, { videoId, status })`：仅老孙。`DONE` 时写 `done_at / done_by_*`；`OPEN` 时清空。
- `adoptFinalIntakes(db, actor, { videoId, intakeIds?: string[]; all?: boolean })`：仅老孙。目标记录必须 `applied = false`；按 `seq` 升序逐条应用（3.2），写 `applied = true, applied_at`。两态下都允许采纳。
- 以上都写一条 `insertAudit`（动作名 `V19_FINAL_STATUS_CHANGED` / `V19_FINAL_INTAKE_ADOPTED` / `V19_FINAL_SAVED`）。

## 四、接口

### 4.1 `GET /api/videos/[id]/analysis/v19`

响应 `V19StudioModel` 增加：

```ts
final: {
  id: string | null;            // 虚拟时为 null
  status: "OPEN" | "DONE";
  doneAt: string | null;
  doneByName: string | null;
  updatedAt: string;
  pendingCount: number;         // applied = false 的记录数
  isVirtual: boolean;
} | null;                       // 案例尚无真实版本时为 null
```

- `?version=final` → `current` 返回最终版：`V19CurrentVersion` 形状不变，附加 `isFinal: true`，`id` 为最终版 id（虚拟时 null），`number: 0`，`ownerName: "最终版"`，`ownerUserId: ""`，`baseNumber: null`，`basePayload: null`，`isMine: false`。同时响应多带 `finalTrace: { originPayload: V04DraftPayloadV1; intakes: V19FinalIntake[] }`，`V19FinalIntake = { id, seq, kind, targetKey, targetLabel, value, source, sourceVersionNumber, actorName, applied, createdAt }`。
- 不带 `?version` 时：`final` 存在（含虚拟）→ `current` 即最终版；否则原规则。
- 老孙可编辑最终版：`viewerCapabilities.canEdit` 在最终版视角下 = `isCaseReviewer(actor.displayName)`。
- 类型放 `lib/v19-ui-model.ts`，与现有 `V19StudioModel` 同处。

### 4.2 `PUT /api/videos/[id]/analysis/v19`

不改形状。`basedOnVersionId: "final"` 走 3.5；否则走 3.4。响应多 `finalIntake`。

### 4.3 `POST /api/videos/[id]/analysis/v19/final`（新增）

```ts
body: { action: "DONE" } | { action: "OPEN" } | { action: "ADOPT"; intakeIds?: string[]; all?: boolean }
```
用 `v04Route(request, { mutation: true }, ...)` 包装；非老孙 403。响应返回最新 `final` 摘要（4.1 的 `final` 对象）与 `ADOPT` 时 `adopted: number`。

### 4.4 评论 `GET /api/videos/[id]/review`

`loadCaseReview` 改为按案例取评论：`SELECT ... FROM analysis_version_comments WHERE video_id = ?`，每条附 `versionId` 与 `versionLabel`（`v2` / `最终版`；普通版本用 `analysis_versions.version_number` 联查，最终版用 `analysis_final_versions.id` 匹配）。`CaseReviewModel.comments` 元素增加 `versionId: string; versionLabel: string`。`stars` 仍按 `?version=` 指定的版本取；`version` 是最终版 id 时 `stars = null`、`canRate = false`（新增字段，前端据此不渲染评分）。写评论时 `versionId` 校验：属于该案例的普通版本或最终版；最终版为虚拟（还没 id）时前端不给入口。

## 五、前端（`components/v04/V04StudioClient.tsx` 及子组件）

13. **版本菜单**：最上方一行 `最终版`（金色）+ 状态胶囊 + 未纳入计数（有则显示）+ 更新时间 + 一行灰字说明“集大成版：每一处内容都取各版本里最新的那次修改；进行态自动汇入，定稿后停止；只有老孙能直接编辑。”；其余行不变；底部说明改为“进入页面默认展示最终版”。「你还没有版本，可手动新建」的基版下拉里加一项“最终版（当前汇聚结果）”——注意 `createV19VersionFrom` 需支持 `baseVersionId === "final"`：以最终版 payload 为快照创建，`base_version_id / base_version_number` 为 null，并在标签里显示“基于最终版”（需要 `analysis_versions` 加可空列 `base_is_final BOOLEAN NOT NULL DEFAULT false`，写进同一份 migration）。
14. **顶栏**：最终版时版本按钮显示 `最终版` + 状态胶囊；隐藏「比较」；右侧出现 `默认 | 溯源` 分段开关；老孙再多一个「✓ 定稿」／「取消定稿（N 处待采纳）」按钮。
15. **视频下方横幅**（最终版时）：进行中——“各版本的每一处修改都会自动汇入这里，后改的覆盖先改的”；已定稿——“老孙于 X 定稿，此后其他版本的修改不再进入最终版”；有未纳入时追加“定稿期间有 N 处修改未纳入”，老孙有「全部采纳」，非溯源视图有「到溯源视图逐条看」。

17. **普通版本保存后的 toast**：`finalIntake.merged` → “「X」的修改已同步进入最终版”；否则 → “最终版已定稿，「X」的修改未纳入最终版，等老孙取消定稿后采纳”（警示色）。
18. **溯源视图**：每个可编辑字段下方渲染该字段的来源链：`originPayload` 里的值作为第一行（`v1 · 原稿`），之后是 `intakes` 中 `kind = FIELD, targetKey` 相同的记录按 `seq` 升序；最后一条 `applied` 的标「当前采用」（高亮），之前的 applied 标「已被覆盖」，`applied = false` 标「未纳入」（琥珀色）并给老孙「采纳这一版」按钮；`source = FINAL_DIRECT` 的版本号显示为「最终版·直接修改」。结构类未纳入记录（INSERT/REMOVE）在横幅下方列成一组“结构改动未纳入”，每条一句话（如“v3 张三 在桥段02后插入镜头”）+ 采纳按钮。字段的 `originPayload` 里不存在目标（后插入的镜头）时不显示原稿行。
19. **默认视图** 的 hover 标题：`点击编辑 · 来自 v2·李晓芸 08-24 11:05`（非老孙为 `最终版只有老孙可以编辑 · 来自 …`）。
20. **评论气泡**（`V19ReviewComment.tsx`）：改为列表，按写入时间升序，每条前缀版本标签（`v2` / `最终版`），本版那条高亮“本版”；老孙在本版没有评论时显示输入区（发布），本版已有则该条有「编辑」；别版的条目对老孙显示“切到该版可改”，对其他人显示“只读”。按钮计数 = 全部版本评论数；本版有评论时按钮描边实色。`commentsByTarget` 改为返回 `Map<targetKey, CaseReviewComment[]>`。
21. **评分**：最终版不渲染 `V19AssignmentRating`。
