# 开发阶段与验收计划

文档版本：V0.6  
说明：本文只做产品与工程规划，不代表已开始业务代码开发。
平台架构基线：A0.1  
当前交付专业域：`AD_VIDEO`

阶段1工程实现以《技术选型与阶段1工程设计》T0.1为建议基线。T0.1不构成独立阶段0，确认后直接进入本文件的阶段1工作包。

## 1. 总体策略

按照“最小公共边界固化—广告域个人反写—团队学习—多人共识—运营完善—AI辅助”推进。

AI 自动拆解必须排在完整的多人闭环之后。

```text
已确认规划基线
  → 固化公共对象、专业域和版本契约
  → 极简视频展台、播放与个人反写
  → 搜索、视频创意投票、公开作业与百分制互评
  → 两轮评审、持续共创、管理员精修与共识
  → 管理员统计、数据导出、积分、权限和上线加固
  → AI辅助试点
```

本规划包直接作为MVP实施依据，不设置作为开发前置门槛的独立阶段0原型、阶段0技术方案或3–5份真实作业试批。T0.1属于阶段1内部工程设计，实施参数随对应功能锁定，不新增阶段。

公共底座边界不是一个新增的独立开发阶段，而是阶段1数据契约评审和建模的组成部分。只实现支撑广告MVP所需的最小公共外壳，不建设地产字段、万能动态表单、插件运行时或跨域页面。

## 2. 阶段1：基础平台与个人反写

建议周期：3–4周

### 范围

- `ProfessionalDomain`及首个专业域 `AD_VIDEO`；
- 公共 `AnalysisSubject`，广告视频案例作为强类型扩展；
- 公共作业、答案修订和提交快照外壳；
- 平台工作流、专业体系、评分量表和交换协议四类版本边界；
- 企业微信登录、用户和部门标签；
- 单一公司空间；
- 基础角色权限；
- 训练任务；
- 不限格式、大小和时长的视频文件上传；
- 原上传者安全替换误传原视频，保留案例及其全部分析关系；
- 分片上传、断点续传、安全扫描和兼容播放；
- 公司内部站内播放，普通成员不提供原片下载；
- 重复检测；
- 极简视频首页和播放器；
- “脚本及创意分析”与“作业／逆向脚本”入口；
- 案例／作业纵向单页；
- 个人逐镜脚本；
- 13列逐镜表格手动调列宽及本机偏好保存；
- 9＋10标注；
- 自动保存、校验和提交快照；
- 基础回收站和审计。

### 验收标准

1. 负责人可创建绑定 V0.2 的训练任务；
2. 成员使用企业微信身份登录，部门标签正确；
3. 系统只有一个公司空间；
4. 成员可直接上传任意格式、大小和时长的视频文件；
5. 大文件可以断点续传；
6. 系统保存原文件、贡献人和权利声明；
7. 不兼容源格式可以生成播放副本，普通成员只能站内播放；
8. 重复案例有提示且不会静默复制；
9. 首页以统一视频展台展示作品，不出现行业分类树或密集管理面板；
10. 点击视频封面可以直接播放，关闭后回到原滚动位置；
11. 用户可从视频进入“脚本及创意分析”或空白“作业／逆向脚本”；
12. 用户在同一纵向页面完成13列逐镜脚本、A1–A9、B1–B10和总结；
13. A3级联选项和A4独立标注正确；
14. 自定义选项要求说明；
15. 草稿自动保存且提交前仅作者和管理员可见；
16. 提交生成不可变快照，提交后公司成员可见；
17. 删除默认进入回收站。
18. `AD_VIDEO`被登记为专业域，视频案例通过公共逆向对象身份进入任务和作业流程；
19. 公共任务、答案和提交快照不以播放器、镜头、时间码或A/B字段作为必填前提；
20. 广告视频答案仍使用强类型逐镜和V0.2结构，A1–A9、B1–B10含义未改变；
21. 所有提交可以追溯专业域、专业体系版本和不可变快照；
22. 普通用户仍直接进入视频展台，不出现未实现的地产入口或专业域选择步骤。
23. 原上传者可以替换误传视频；切换成功后案例ID、脚本、作业、评分和分析不变，替换操作可审计；
24. 非原上传者不能替换视频；替换失败时原视频仍可播放；
25. 编辑和阅读逐镜脚本时可拖动13列表头边界调整宽度，刷新后本机偏好仍保留，并可恢复默认值。

### 测试重点

- 自动保存冲突；
- 长脚本性能；
- 文件上传中断；
- 超大文件、长视频和非常见格式；
- 转码失败时提示管理员处理，普通成员仍不能下载原片；
- 重复提交；
- 表单数量上限；
- 多端同时编辑。
- 原视频替换的上传者权限、失败回滚、旧文件隔离和审计记录；
- 列宽最小值、单列／全表恢复默认、本机持久化和同页同步；
- 公共模块对广告域对象的反向依赖；
- 专业域与体系版本不一致；
- 公共逆向对象与广告视频扩展的一致性。

## 3. 阶段2：团队案例站与百分制互评

建议周期：3–4周

### 范围

- 专业域接入契约中的评分呈现、答案定位和比较能力；
- 公共评审引擎与 `AD_VIDEO` 评选模板分离；
- 团队视频作品展台；
- 按创意级别和标签搜索；
- 视频、用户、已提交作业和评论搜索；
- 最新、创意综合分和精选排序；
- 已提交个人作业公开；
- 五档视频创意奖级投票；
- 创意综合分、展示级别和正式排名；
- 案例收藏和推荐；
- 百分制作业评分；
- 平时次要评分入口与评审会显著任务入口；
- 按新版100分量表逐项评分；
- 逐镜脚本还原35分；
- 镜头创意点评20分；
- 19项标注依据不计分；
- 各内容旁的分值输入位；
- 固定总分计数器；
- 鼠标移入即显示、移出即消失的评分指南；
- 字段批注、质疑和建议修订；
- 高分与推荐候选；
- 个人学习档案基础版；
- 通知中心基础版。

### 验收标准

1. 公司空间全体成员能看到全部视频、已提交作业、标签和评分；
2. 普通成员可以查看但不能编辑他人作业；
3. 普通成员不能查看他人的未提交草稿；
4. 评分绑定具体作业修订和量表版本；
5. 自评分不进入有效质量统计；
6. 同一用户对同一作业修订只有一份有效正式评分；
7. 全部计分项严格合计100分，单项不允许超过满分；
8. 字段反馈可精确定位A/B字段；
9. 原作者能看到分数和批语，但评分者不能修改原文；
10. 个人档案能展示训练、贡献、同行均分和评分明细；
11. 高分和推荐作业能形成讨论候选；
12. 页面固定显示实时总分、已评分项和未评分项；
13. 鼠标移入评分指南区域后立即显示，移出后立即消失；
14. 19项标注依据不填不影响作业得分或评分提交；
15. 评分输入位于对应镜头、核心判断或9＋10字段旁，不要求在独立评分页和内容页之间往返；
16. 作业和评分修改约1秒自动保存，页面只保留统一发布或正式提交动作；
17. 写作业、修订和批改时播放器始终在视线范围内；
18. 每名用户对每个视频只有一张有效创意奖级票；
19. 大奖、金、银、铜、入围正确换算为100、80、60、40、20分；
20. 创意综合分和展示级别计算正确；
21. 少于3票的视频不进入正式排名；
22. 视频创意综合分与作业100分分别展示、分别排行；
23. 可以按创意级别和标签找到对应视频。
24. 可以按用户找到其公开作业和评论；
25. 搜索结果不会出现他人的未提交草稿。
26. 平时评分入口不会挤占播放、分析和练习主操作。
27. A1–A9、B1–B10均能在原位悬停查看V0.2附表预设值、类别、解释和选择规则；
28. 点击预设值能够加入或取消答案，“其他”能继续自由输入，原有自由文本答案不丢失。

### 测试重点

- 权限穿透；
- 评分版本绑定；
- 修改和删除评分后的重算；
- 新版100分各子项合计、边界值和未评分状态；
- 总分计数器实时重算；
- 评分指南悬停显示、移出消失，且不依赖点击；
- 搜索和筛选准确性；
- 视频、用户、作业、评论混合索引的权限过滤；
- 创意奖级改票、并发投票和综合分重算；
- 票数门槛、同分排序和级别边界；
- 重复浏览和互赞异常。
- 19项附表词表与V0.2源表逐项一致；
- 预设多选、取消、自定义输入与约1秒自动保存兼容。

## 4. 阶段3：高分讨论、管理员精修与共识

建议周期：3–4周

### 范围

- 通用分歧记录、修订理由、置信度和金标准来源链；
- `AD_VIDEO`“最佳整体标注”与公共金标准状态映射；
- 多人标注选择；
- 周／双周讨论候选和确认；
- 管理员勾选作业创建两轮评审活动；
- 首轮环形互评任务；
- 作业不足时的自由补评池；
- 多评分加权汇总；
- 首轮严格大于80分晋级；
- 第二轮新评分者分配；
- 前两名最佳作业奖；
- 活动进度、排名、分数分布和异常评分处置；
- 追加式共创；
- 管理员优秀Mark；
- 最佳整体标注组装、发布和来源追踪；
- 管理员专家批阅分；
- 管理员精修版及修改差异；
- 19字段差异比较；
- 逐镜脚本辅助对齐；
- 共识草稿；
- 分歧决议记录；
- 共识审核和发布；
- 共识修订；
- 个人标注一致度；
- 批改可靠度基础统计。

### 验收标准

1. 至少3名成员可对同一案例独立提交并相互批改；
2. 只能比较同一体系版本；
3. 能识别完全一致、部分一致和不一致；
4. 主标签、副标签和特殊角色分别比较；
5. 逐镜脚本可按时间码辅助对齐；
6. 共识是独立数据集；
7. 每个分歧可以记录采纳来源和理由；
8. 管理员精修和共识发布都不修改个人原始结果；
9. 共识修订保留历史；
10. 共识发布后生成每人的字段比较明细；
11. 字段批注能够与精修版和共识结果比较；
12. 管理员精修版显示原稿、修改后和修改理由；
13. 高分与高价值作业能进入周／双周讨论；
14. 已发布精修版和共识可被团队查看；
15. 管理员可以勾选多个已提交作业发起活动；
16. 活动发布后候选作业修订不会被后续修改替换；
17. 全员、部门和指定成员参与范围均正确；
18. 系统能统计参与率、均值、中位数、高低分、标准差和分布；
19. 管理员排除无效评分后可以重算，并保留原评分和旧统计快照；
20. 活动结果经管理员确认后才向参与者发布。
21. 20名参与者、20份作业能生成2评1、3评2直至1评20的完整环形关系；
22. 作业少于参与者时每份作业至少有一名指定评分者，多余人员进入自由补评；
23. 多评分按权重公式正确汇总，MVP普通同行权重为1；
24. 首轮80分不晋级，超过80分晋级；
25. 第二轮优先排除已在首轮评过同一候选的评分者；
26. 第二轮能评出前两名，并按规则处理第二名同分；
27. 成员可以向镜头、字段和整体分析追加共创贡献；
28. 共创贡献不会覆盖既有标注或他人贡献；
29. 管理员可以添加优秀Mark；
30. 管理员能组装、发布和回看版本化最佳整体标注；
31. 最佳整体标注每项都能追踪来源。

### 测试重点

- 多人结果缺失；
- 自定义标签比较；
- A3层级比较；
- B5双视角比较；
- B9组合结构比较；
- 共识发布幂等性；
- 共识修订后的指标重算；
- 管理员精修权限与原稿保护；
- 评选活动候选冻结和评分幂等；
- 活动截止并发、改分截止边界和统计重算。
- 环形任务在自评冲突、缺交作业和多人无作业情况下仍完整；
- 自由补评重复提交和指定任务重复生成；
- 晋级线80、80.0001及显示四舍五入边界；
- 第二轮评分者排除和目标人数不足；
- 共创并发追加、贡献修订和软删除；
- 优秀Mark撤销及最佳整体标注来源完整性。

## 5. 阶段4：Excel、积分与上线加固

建议周期：2–3周

### 范围

- 公共导出清单及交换协议版本；
- V0.2广告域导出器；
- SunOS交换包边界和幂等标识，不含实时同步；
- V0.2 Excel 严格导入；
- 个人、多方、创意投票、作业评分、精修和共识导出；
- 生成范例、评估器范例和模板导出预设；
- 共创贡献、优秀Mark和最佳整体标注导出；
- CSV和JSONL数据集导出；
- 行为统计、评分汇总和质量审核后台；
- 导入错误报告；
- 积分事件；
- 分榜排行榜；
- 奖励台账；
- 完整版权处置；
- 审计日志；
- 回收站恢复和永久删除；
- 性能、安全、备份和监控。

### 验收标准

1. V0.2四张表能够被正确识别；
2. 导入必须选择用户、案例和体系版本；
3. 导入失败不会产生半完成正式数据；
4. V0.1不会按行号误映射到V0.2；
5. 只有管理员可以执行结构化数据导出；
6. 导出文件重新导入后关键数据一致；
7. 积分来源逐项可查；
8. 排行榜显示周期、样本和规则版本；
9. 奖励支持发放和撤销；
10. 普通成员可以站内播放视频，但页面和接口均不提供原片下载；普通成员也无法导出结构化数据；
11. 回收站能恢复完整关联；
12. 权限、安全、备份和故障恢复演练通过；
13. 管理员可以按周期、部门、用户、任务和活动查看行为统计；
14. 视频投票与作业评分能分别汇总数量、均值、中位数、分布和离散度；
15. 管理员可以校订视频元数据、创建作业校订版并处置无效评分；
16. 数据导出包含用途、来源、体系版本、量表版本和文件哈希；
17. 普通成员无法访问管理员统计、质量治理或导出后台。
18. 最佳整体标注能够按V0.2、CSV和JSONL导出并保留来源链；
19. 导出后的优秀Mark、采纳关系和管理员校订可以还原。

阶段4结束时，第一版MVP才算完整交付。

## 6. 阶段5：AI辅助试点

启动条件：

- 人工多人闭环稳定运行；
- 已积累足够的V0.2个人提交和共识；
- 共识质量经过抽检；
- AI权限、版权和数据用途得到批准。

可能范围：

- AI逐镜建议；
- AI转写建议；
- AI 9＋10标注建议；
- 人工接受、拒绝和修改；
- AI与个人、共识比较；
- 模型和提示版本追踪。

### 验收边界

- AI只写入独立建议通道；
- AI不能直接提交个人标注；
- AI不能直接发布共识；
- AI故障不影响人工流程；
- 所有AI结果绑定模型、提示和体系版本；
- 在质量达标前明确标记为“辅助建议”。

## 7. 端到端系统验收方案

不进行3–5份真实作业试批，也不把评分量表校准作为开发或上线前置条件。系统功能验收使用至少1条固定测试视频，验证评分计算、权限和完整业务闭环。

参与者：

- 至少3名普通成员；
- 另准备20个模拟成员身份验证环形互评算法；
- 1名训练负责人；
- 1名管理员，可与负责人兼任。

端到端任务：

1. 每人提交至少1条案例；
2. 至少1条案例由3人独立标注；
3. 至少3人对同一视频投创意奖级并形成正式综合分；
4. 搜索到指定用户及其已提交作业和评论，同时确认草稿不可见；
5. 每人按照新版100分量表批改至少2份他人作业；
6. 使用20名模拟参与者和20份作业生成首轮环形互评；
7. 再模拟作业少于参与者，检查自由补评池；
8. 活动结束后检查加权分、高低分、分布和参与率；
9. 验证80分不晋级、超过80分进入第二轮；
10. 第二轮由其他成员评分并发布前两名最佳作业奖；
11. 至少3名成员向同一视频的不同位置追加共创贡献；
12. 管理员添加优秀Mark并组装最佳整体标注；
13. 选出高分或高价值作业进行一次模拟周会；
14. 管理员对至少1份作业创建精修版；
15. 对目标案例完成共识；
16. 检查个人一致度和批改可靠度；
17. 由管理员导出一个包含最佳整体标注的评估器范例数据包和V0.2文件；
18. 删除并恢复一个测试案例；
19. 模拟一个播放副本处理失败但原文件可下载；
20. 检查行为统计和审计日志。

## 8. 质量门槛

### 功能

- P0需求全部通过；
- 不存在阻断核心闭环的缺陷；
- 权限缺陷按最高优先级处理。

### 数据

- 标注版本绑定率100%；
- 提交快照完整率100%；
- 共识对个人结果零覆盖；
- 管理员精修对个人原稿零覆盖；
- Excel关键字段往返一致；
- 评分、精修和奖励可追溯；
- 评选活动候选、量表、参与者和结果快照可追溯；
- 评审轮次、指定任务、自由补评、晋级和奖项可追溯；
- 共创、优秀Mark和最佳整体标注来源可追溯；
- 导出数据具有明确用途和来源链。

### 可用性

- 新用户在不阅读研发说明的情况下能完成一次提交；
- 新用户可以从首页在一次点击后开始播放视频；
- 首页不需要理解行业分类或后台信息结构；
- 用户无需页面跳转即可纵向完成一份作业；
- 标注员能明确区分A3、A4和B2；
- 播放失败时用户知道下一步操作；
- 提交前错误提示能定位到具体字段或镜头；
- 每个计分内容旁有打分位置，固定总分计数器始终可见；
- 评分指南能在鼠标移入后立即出现、移出后消失；
- 桌面、Pad和手机均能完成浏览、播放、进入脚本与开始作业；
- 普通用户无需进入管理后台即可完成五类核心动作；
- 管理员可以在独立后台完成统计、校订、评选和导出。

### 安全与版权

- 企业微信外部身份无法进入公司空间；
- 上传文件安全扫描有效；
- 结构化数据导出仅管理员可用；
- 权利状态可查询；
- 下架、禁用和删除操作有审计。

## 9. 建议研发工作流

每个阶段采用：

1. 需求评审；
2. 数据契约评审；
3. 开发；
4. 自动化测试；
5. 功能验收；
6. 缺陷修复；
7. 阶段复盘。

任何标注字段变更，必须先发布新的体系版本，再修改产品配置和导入导出规则。

每次数据契约评审还必须检查：

1. 公共模块是否新增了对视频、镜头、时间码或A/B字段的依赖；
2. 专业答案是否仍由专业域强类型结构管理；
3. 作业、答案、评分、审定和导出是否绑定正确专业域与版本；
4. 广告域页面和流程是否发生非预期回归；
5. 是否误把尚未稳定的地产需求提前写入公共模型。
