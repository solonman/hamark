# 决策确认与剩余待办

文档版本：V0.6

## 1. 已确认事项

### D-001 企业微信登录

- 使用企业微信身份登录；
- 系统保存稳定的企微成员标识；
- 姓名、头像和部门信息可以从企微同步。

状态：已确认。

### D-002 单一公司空间

- 第一版只有一个公司空间；
- 不建设多租户或敏感项目隔离；
- 企微账号带部门归属标签；
- 部门标签用于筛选、统计和展示，不构成内容保密边界。

状态：已确认。

### D-003 MVP直接上传视频

- 第一版由成员直接上传视频文件；
- 暂不建设视频网址解析；
- 暂不考虑把网址自动转换成可观看视频。

状态：已确认。

### D-004 视频上传不设置业务限制，原片不向普通成员下载

- 格式不限；
- 大小不限；
- 时长不限；
- 普通成员只在站内播放，不提供原片下载入口；
- 工程层保留安全扫描、分片上传、断点续传、兼容性检测和必要转码；
- 原文件始终保留，兼容播放副本单独生成，仅管理员按治理流程处理原文件。

这里的“不限”指不设置产品业务门槛，不代表服务器可以没有安全和稳定性保护。

状态：已确认。

### D-005 结构化数据导出受限

- 公司成员可以在线查看案例、已提交作业、标签和评分；
- 公司成员可以站内播放内部视频，但不提供原片下载；
- 只有管理员可以导出结构化标注、创意投票、作业评分、评审轮次、共创、最佳整体标注、共识和用户学习数据；
- 导出用途包括未来生成范例、评估器范例、模板和归档；
- 导出保留版本、来源、版权和用途信息；
- 导出行为必须审计。

状态：已确认。

### D-006 公司内部全部可见

- 全部案例可见；
- 已提交个人作业可见；
- 个人草稿提交前仅作者和管理员可见；
- 全部标签可见；
- 全部同行评分和批语可见；
- 全部精修版和共识可见；
- 产品鼓励相互阅读、批改和评选。

状态：已确认。

### D-007 编辑不互相覆盖

- 普通成员只能编辑自己的作业；
- 普通成员可以对他人的作业评分、批注和提出修改建议；
- 管理员可以校订他人的作业；
- 管理员校订形成独立“管理员精修版”；
- 管理员可以直接修正视频元数据和标签，但保留字段历史；
- 管理员可以将无效评分排除出汇总，但不物理删除原评分；
- 原始个人提交和历史版本始终保留；
- 所有管理员修改有差异记录和审计。

状态：已确认。

### D-008 共识按需触发

- 不是每个案例都必须形成共识；
- 高分、争议大、学习价值高或需要进入正式数据集的案例进入共识；
- 至少2份个人提交才能创建正式共识；
- 端到端验收案例至少3份个人提交。

状态：采用已建议默认值。

### D-009 百分制作业评分

每份作业满分100分，不再采用“基础50分＋创意展开50分”的旧分组。逐镜脚本还原是核心大题，相当于作文。

分值结构：

| 模块 | 分值 |
|---|---:|
| 商业意图 | 3 |
| 创意母题 | 5 |
| 故事梗概 | 4 |
| 创意思维链 | 10 |
| 逐镜脚本还原 | 35 |
| A1–A9 | 9 |
| B1–B10 | 10 |
| 镜头创意点评 | 20 |
| 全篇创意总结 | 4 |
| 合计 | 100 |

19项标注依据不计分，也不为获得分数而强制填写。

状态：已确认。

### D-010 周／双周作业机制

- 负责人按周或双周发布作业；
- 成员交作业；
- 成员相互批改；
- 高分和高价值作业进入每周一或双周一讨论；
- 管理员有精力时进行专家批阅和精修；
- 精修数据成为高质量训练数据。

状态：已确认。

### D-011 单页纵向体验

- 一条案例的观看、逐镜、9＋10标注、总结、阅读、评分和批注放在同一页面；
- 主要操作依靠鼠标纵向滚动；
- 使用固定视频窗、页内目录和锚点定位；
- 不为每一个填写模块跳转新页面；
- 编辑、阅读、批改和管理员精修是同一页面的不同模式。

状态：已确认。

### D-012 奖励和排行榜

- MVP先做积分、徽章、精选、示范作业和人工奖励台账；
- 按周／双周及累计周期展示；
- 高分榜、逐镜还原榜、镜头创意点评榜、进步榜和批改可靠度榜分别展示；
- 实物或现金在线下处理。

状态：采用已建议默认值，并根据作业周期调整。

### D-013 其他默认规则

- 回收站默认保留30天；
- V0.1作为独立历史版本，不自动覆盖为V0.2；
- Excel长期作为管理员导入导出接口，系统数据库是事实源；
- 第一版以专业分析工具为主体，辅以适度作业感和排行榜；
- AI在人工多人闭环之后开发。

状态：采用已建议默认值。

### D-014 评分界面与开发起点

- 每个评分内容旁设置对应分值输入位；
- 页面固定显示实时总分计数器、已评分项和未评分项；
- 鼠标移入评分指南区域后立即显示，移出后立即消失；
- 不再依赖点击：鼠标移开后浮窗立即消失；
- 不设置作为开发前置门槛的独立阶段0原型和阶段0技术方案；
- 不经过3–5份真实作业试批；
- 规划基线确认后直接进入MVP实施。

状态：已确认。

### D-015 极简视频展台

- 首页像高品质电影网站或获奖广告作品展台；
- 所有作品统一陈列，不建立汽车、食品等行业分类；
- 点击视频封面直接播放；
- 每个视频提供“脚本及创意分析”和“作业／逆向脚本”入口；
- 首次进入作业时打开与视频绑定的空白长文档；
- 已有草稿时继续原草稿；
- 桌面、Pad和手机使用相同的信息层级；
- 视觉强调大画面、留白、克制文字和简洁操作。

状态：已确认。

### D-016 视频创意奖级投票

- 奖级只有大奖级、金奖级、银奖级、铜奖级、入围级；
- 每名成员对每个视频只有一张有效票；
- 默认换算分为100、80、60、40、20；
- 创意综合分取全部有效票换算分的算术平均值；
- 少于3票时显示“票数不足”，不进入正式排名；
- 排名按综合分、有效票数、最近有效投票时间排序；
- 支持按创意级别和标签搜索；
- 视频创意综合分与个人作业100分分开保存和排行。

状态：奖级和产品方向已确认；换算分、3票门槛及同分排序作为MVP默认规则。

### D-017 普通用户五类动作

普通用户界面只突出：

1. 看片；
2. 查看别人已提交的脚本分析；
3. 练习并提交自己的作业；
4. 搜索视频、标签、用户、已提交作业和评论；
5. 给视频投创意奖级或给别人的作业评分。

状态：已确认。

- 可以按生成范例、评估器范例、模板或归档目的导出；

状态：已确认。

### D-019 评选活动

- 管理员从已提交作业中勾选候选；
- 活动按轮次冻结候选修订、参与者、评分任务和评分量表版本；
- 参与范围支持全员、部门或指定成员；
- 作者自评分不进入有效活动分；
- 首轮采用环形互评，2号评1号、3号评2号并循环；
- 作业少于参与者时，多余人员进入自由补评池；
- 普通同行评分默认权重为1；
- 首轮未四舍五入综合分严格大于80分进入第二轮；
- 第二轮优先由未评过该候选的其他成员评分；
- 第二轮最高分前两名获得当次最佳作业奖；
- 系统统计参与率、指定互评完成率、自由补评数、有效评分人数、均值、中位数、高低分、标准差和分布；
- 管理员审核后发布活动结果。

状态：已确认；第二轮默认目标3名评分者及同分规则作为MVP默认值。

## 2. 剩余实施待办

这些事项不改变产品方向，可在技术设计阶段确认。

### I-001 企业微信接入参数

- 企业ID；
- 自建应用或第三方应用；
- 回调域名；
- 需要同步的成员和部门范围；
- 离职、调岗和部门变更同步策略。

### I-002 管理员名单

需要确定：

- 谁可以创建管理员精修版；
- 谁可以确认发布分；
- 谁可以发起评选活动和发布结果；
- 谁可以添加优秀Mark并发布最佳整体标注；
- 谁可以查看行为统计并处置无效评分；
- 谁可以导出结构化数据；
- 谁可以永久删除数据。

这些权限可以由不同管理员角色承担。

### I-003 视频存储与处理基础设施

业务不限制格式、大小和时长，但技术设计仍需确定：

- 对象存储；
- 单次分片大小；
- 断点续传方案；
- 安全扫描；
- 转码队列；
- 浏览器播放格式；
- 原文件和播放副本的备份；
- 带宽和成本监控。

基础设施保护不能表现为未经确认的业务限制。

T0.1建议采用：

- 生产使用腾讯云COS或同等级S3兼容私有对象存储；
- 浏览器使用最小权限临时凭证分块直传；
- 本地开发使用MinIO；
- BullMQ＋Redis调度独立FFmpeg工作进程；
- 阶段1生成H.264＋AAC MP4播放副本和封面；
- 暂不生成多码率HLS，不默认启用CDN。

剩余待确认的是实际云账号、地域、存储桶、临时授权角色、备份和成本参数。

### I-004 企业微信通知

登录确定使用企微后，仍需决定：

- MVP只做站内通知；
- 或同时发送企微作业提醒、截止提醒、批改提醒和讨论通知。

建议：站内通知为P0，企微消息为P1。

### I-005 首轮作业周期

每个任务可以配置周作业或双周作业。上线前需要确定第一次采用：

- 每周提交、每周一讨论；
- 或双周提交、双周一讨论。

该选择不影响数据结构。

### I-006 技术基线确认

《技术选型与阶段1工程设计》T0.1建议：

- TypeScript模块化单体；
- Next.js Web＋NestJS REST API；
- PostgreSQL＋Prisma多Schema；
- BullMQ＋Redis后台任务；
- S3兼容存储抽象，生产优先腾讯云COS；
- 独立FFmpeg／安全扫描Worker；
- Docker部署，不引入Kubernetes和微服务；
- 阶段1不建设独立搜索服务、多码率HLS或企业微信消息通知。

状态：待确认。确认后即可建立工程仓库、数据库迁移、V0.2种子和本地开发环境。
