# 部署交接与正式上线清单

版本：H0.1  
日期：2026-08-02  
对象：负责域名、服务器、企业微信接入和正式发布的开发／运维同事

## 1. 当前工程状态

当前版本是完整可运行的单视频演示纵切版。当前技术实现为Next.js／vinext同域应用，关系数据通过 `DATABASE_URL` 连接 Supabase Postgres，视频对象通过腾讯云 COS 私有桶存储。

当前运行时环境变量：

| 数据 | 配置 | 用途 |
|---|---|---|
| 关系数据 | `DATABASE_URL` | 视频元数据、作业、镜头、19项标注、快照、评分和审计 |
| 视频对象 | `COS_REGION`、`COS_BUCKET`、`COS_SECRET_ID`、`COS_SECRET_KEY` | 原视频和替换后的对象文件 |

`web/.env.example` 是配置模板，不包含真实密钥。`web/.openai/hosting.json` 仅保留历史 Sites 元数据，不再作为数据库或视频存储配置来源。

## 2. 权威业务基线

任何部署或迁移不得修改以下含义：

- 专业域：`AD_VIDEO`；
- 标注体系：V0.2；
- 创意构成A1–A9共9项；
- 故事组织B1–B10共10项；
- 作业评分：RUBRIC-V0.4，合计100分；
- 每份标注和评分必须绑定版本；
- 个人草稿、个人提交、评分、管理员精修和最终共识不得物理覆盖；
- 删除默认进入回收站；
- 普通成员不得获得原视频下载入口；
- 第一版优先完成多人作业和互评闭环，不提前开发AI自动拆解。

权威表格位于本包 `参考资料/视频广告创意反向标注训练空白表_V0.2.xlsx`。

## 3. 两条发布路径

### 3.1 私有演示发布

目标：尽快获得离开开发电脑也能打开的受控演示网址。

可沿用当前 Supabase Postgres 和 COS 存储适配，不迁移业务模型。发布时必须：

1. 保持站点私有或明确的人员白名单；
2. 使用受控的 Supabase 项目和私有 COS 桶，不把本地演示数据当成云资源；
3. 只迁移确认需要的《欢迎回家》演示案例；
4. 不把当前演示身份当作多人身份系统；
5. 不绑定企业微信正式入口。

此路径仅用于演示，不作为公司正式生产验收。

### 3.2 公司正式生产发布

建议方案：

| 模块 | 首版建议 |
|---|---|
| 域名 | 优先使用公司现有已备案根域的子域名，如 `reverse.company.com` |
| 云账号 | 公司实名认证的腾讯云主账号，不使用个人账号 |
| 地域 | 选择离主要办公地点最近的中国大陆地域，数据库、Redis和COS同地域 |
| 计算 | 首期2核4GB起步的云服务器／容器计算；Web、API和Worker分容器 |
| 数据库 | 托管PostgreSQL，启用自动备份和时间点恢复能力 |
| 队列 | 小规格托管Redis；Worker设置独立CPU和内存配额 |
| 视频 | 私有COS、分块直传、临时授权、Range播放、禁止公共读 |
| 网络 | HTTPS；首版不默认启用CDN，先观察办公室播放体验 |
| 身份 | 企业微信自建应用OAuth＋服务端会话＋部门同步 |
| 发布 | 预发布和生产环境分离；使用同一构建产物逐级晋升 |

正式架构和验收以 `docs/09_技术选型与阶段1工程设计.md` 为准，不要求在上线前拆微服务或引入Kubernetes。

## 4. 域名与账号办理

优先向公司IT确认是否已经拥有可用且完成ICP备案的根域名。已有域名时只申请子域名，不应再注册一个仅面向广告专业域的新根域，以便未来接入其他专业域。

如无现有域名：

1. 使用公司营业执照建立腾讯云企业账号和企业实名信息模板；
2. 以公司为域名所有者注册可备案的 `.com` 或 `.cn`；
3. 购买满足备案条件的中国大陆云资源；
4. 完成ICP备案；
5. 配置DNS、HTTPS证书和备案信息；
6. 网站开通后按当地要求完成公安联网备案；
7. 在企业微信自建应用中配置可信域名和授权回调域。

不得把正式域名、云账号、证书或企业微信应用登记在开发人员个人名下。

## 5. 正式上线前的强制工程项

### 身份与权限

- 删除生产环境的 `demo@reverse.local` 身份兜底；
- 未认证请求返回401或进入企业微信授权，不得自动成为演示用户；
- 服务端校验企业ID、成员状态、部门和角色；
- 设置首批管理员和训练负责人；
- Secret仅存于托管密钥／环境变量，不进入源码、构建产物、日志或前端。

### 数据和视频

- 用 `npm run db:migrate` 初始化和升级 Supabase Postgres，它应用 `web/db/bootstrap.ts`——这是 schema 的唯一来源，幂等可重复执行；不依赖请求时动态建表；
- **迁移必须先于代码部署**：2026-08-12 出过一次事故，V0.3 系列代码上线时三个迁移一个都没跑，视频详情页全部 500；
- COS 保持私有桶，服务端通过环境变量签名访问；
- 浏览器使用短期临时凭证分块直传，文件主体不经过应用服务器；
- 播放使用短期受控地址或鉴权代理，禁用公共读和永久URL；
- 迁移视频、作业、镜头、标注、快照、评分和审计时保持原始ID和版本；
- 对迁移前后数量、内容哈希和对象大小做核对。

### 运维与安全

- 建立开发、预发布、生产三套隔离配置；
- 数据库自动备份，并完成一次恢复到独立实例的演练；
- COS启用版本或生命周期策略，回收站保留期由产品负责人确认；
- 配置日志、错误告警、存储量和流量费用预警；
- 日志不得记录作业正文、企业微信Secret、临时上传密钥或完整视频URL；
- 设置上传并发、转码并发和异常文件清理策略；产品界面不人为限制格式、大小和时长，但基础设施必须有容量与费用保护。

## 6. 建议实施顺序

1. 完整运行本包并保存当前验收结果；
2. 确认公司域名、腾讯云账号、部署地域和企业微信管理员；
3. 建立预发布基础设施；
4. 接入企业微信和正式权限，删除演示身份兜底；
5. 完成PostgreSQL、COS和分块上传适配；
6. 只迁移《欢迎回家》演示案例到预发布；
7. 用一条视频完成上传、替换、播放、作业、提交、回看和评分；
8. 完成20人同时编辑、5个同时上传和2个同时转码的容量验收；
9. 完成备份恢复和权限越权测试；
10. 绑定正式域名和企业微信回调，发布生产版本；
11. 生产发布后再迁移确认需要的正式案例数据。

## 7. 上线验收门槛

以下项目全部通过后才允许向公司全员开放：

1. 未登录用户无法读取首页、视频、作业或评分数据；
2. 企业微信成员身份、姓名和部门正确；
3. 外部企业成员不能进入公司空间；
4. 普通成员只能修改自己的草稿和评分；
5. 管理员操作保留审计，不覆盖个人原始答案；
6. 普通成员无法获得原视频下载模式或永久对象地址；
7. 上传中断可以恢复，失败不会生成半成品案例；
8. 替换原视频不改变案例ID、脚本、作业和评分；
9. 所有作业绑定V0.2，所有评分绑定RUBRIC-V0.4；
10. 提交快照不可变，删除进入回收站；
11. 一条《欢迎回家》视频可以完成现场全闭环演示；
12. 生产数据库备份可恢复；
13. 管理员导出权限与普通成员隔离；
14. HTTPS、DNS、企业微信回调和错误告警均正常。

## 8. 交接人需要向业务负责人确认的输入

| 输入 | 用途 |
|---|---|
| 公司现有域名及ICP备案情况 | 决定使用子域还是注册新域名 |
| 腾讯云企业账号和主要办公地域 | 建立正式基础设施 |
| 企业微信CorpID、AgentId、Secret和管理员 | 真实登录联调 |
| 首批管理员、负责人和普通成员名单 | 权限初始化 |
| 预计月上传量、平均视频大小和保留周期 | COS与流量预算 |
| 数据库备份保留期、RPO和RTO | 备份及恢复验收 |
| 正式上线窗口和回滚负责人 | 发布组织 |

任何Secret或证书私钥不得通过本开发包、普通聊天或邮件明文传递。

## 9. 本包演示数据边界

本包 `web/.wrangler/state/` 含内部演示视频、作业和评分，只用于开发复现和受控演示：

- 不得直接同步到公共对象存储桶；
- 不得将站点设为匿名公开；
- 正式迁移前由业务负责人确认保留范围；
- 迁移完成后仍需保持视频私有和成员可见边界。
