## 一、范围

做三样东西，按这个顺序：

1. **地基**：`reports` 一族表、上传与 complete 接口、离线转换脚本（PPT/PDF → 每页图）。
2. **报告库**：首页「报告库」页签从占位空态变成真列表（上传、四种状态、收藏、星级、按周）。
3. **拆解工作台**：把 V2 demo 搬成 React，接现有的版本链／评论／评分口径。

明确不做：机器辅助标注、结构"待人工确认"状态、专家定稿（同视频侧的搁置决定）。

## 二、冻结的产品规则（demo 已确认，实现不得走样）

### 2.1 结构
- 四层：**模块 ＞ 讲述单元（可多级）＞ 页 ＞ 组块**。页是系统事实（PPT 有几页就是几页），组块是在页图上框出来的；需要人"划"的只有模块和单元。
- 模块、单元都是**连续页区间**。任何会把一段拆成不连续两截的移动一律拒绝。
- 页可以只属于模块、不进任何单元（留在模块托盘里）。
- 页被搬空的段自动撤销，不留空框。
- 模块／单元的编号（1、1-1、1-1-1）按页序派生，**不存**；页码范围按所辖页派生，**不存**。
- 模块只有一个「名称」字段：固定候选（营销命题／路线选择／价值故事仓／核心成果／营销行动）＋自由填写。颜色按模块顺序取，与名称无关。

### 2.2 条目（字段清单）
- **第一部分 案例背景与资料**：城市、开发商、项目背景（多行）、业务背景（多行）、相关资料（文件列表）。来源信息（文件名、格式、页数、原页序、**任务类型**、上传人／时间）只读。
- **第二部分 竞争与提报策略**：竞争与提报策略（多行）、报告模型（下拉：标准型／文学章回型／问题章回型／顾问模板型）。
- **模块**：名称、模块间组织关系（下拉）、策略作用（多行）。
- **讲述单元**：名称、单元间组织关系（下拉）、传播／讲述任务、讲述作用、预期心理、候选结论。
- **页**：结构页性质＝过渡页（开关）、页面作用（多行）、本页组织关系（多行）；归属只读，由所在收纳框决定。
- **组块**：名称、内容类型（固定候选＋自由填写）、组块作用（固定多选 12 项）、文风类型（下拉）、组块间组织关系（下拉）、叙述作用（多行）、关键标记；坐标只在页图上画，表单不出现数字。
- 组织关系候选（9 项）固定，不放开自由填写：推导／并列／展开／对比／隐喻·映射／转折／收敛／时间／相对独立。
- 任务类型在**上传时**选定（宣发企划／故事线／宣发阶段性提报／月度总结报告／专项宣发方案），工作台不再出现该字段。

### 2.3 交互（工作台）
- 页序（左）与收纳框（右）两列，分隔条可拖；左列页图按列宽等比放大。
- 按在页图上拖＝搬运；从页图外面按住拉框＝框选；单击选一页，Shift＋单击扩选；点选区外关闭浮出工具栏。
- 搬运到相邻框＝移动边界：拖一页，从它到本段那一头的页一起走；拖动中实时显示落点竖线与说明；非法落点直接拒绝。
- 模块／单元标注框：**只有 × 能关**（点外部、Esc 都不关）；开着期间页序与收纳框只看不动（压暗），hover 页面显示放大预览。
- 页面与组块标注在 modal 里，支持连续框选、选框与卡片双向联动、首页／尾页／翻页，导航条按模块色系、单元深浅着色，已填完打 ✓、在标打 ·。
- 「查看脑图」：模块 → 单元 → 子单元树，节点带页码范围与关键结论（模块取策略作用，单元取候选结论），点节点跳到收纳框。
- 分步引导：空态大版（三步只展开当前步），有结构后缩成一条，可关可唤回。
- 「已填完」的定义：页面作用已填 ＋ 至少一个组块 ＋ 每个组块都填了内容类型与组块作用；动过任一项算「在标」。

### 2.4 评审与互动（与视频侧同口径）
- 评论只开放给评审人（`isCaseReviewer`，即「老孙」），锚定当前版本；开放式条目、模块、单元、页（页面作用）、组块（组块级）各有入口；固定选项条目无入口。
- 评分锚定版本，正文末尾；未评分时非评审人整条不显示；再点当前分数＝撤销。
- 报告库：每人每周三票收藏，一票投给一份报告（同一份报告收不下同一个人的第二票）；再点已投的即撤票，三票投完后再点第四份直接拒绝并提示；星级只展示；按周显示时周内按收藏数排序；**未就绪（页图未生成）的报告不能收藏、不能进入**。

## 三、数据架构

### 3.1 原则
- 报告是独立域，不挂视频侧的 V0.4 契约（`collaboration_workspaces`／词表版本那套）。视频的契约体系是为镜头字段服务的，报告用不上，硬挂只会把两边绑死。
- 版本链复用 V1.9 的**规则**（每人一版、基版快照、默认最新版、时间线不级联——报告没有时间线），不复用它的表。
- 一切派生量（编号、页码范围、已填完）不入库；结构以"页归属"存，段以"首页"锚定，保证版本间逐页可比。

### 3.2 新表

```sql
-- 报告主表（对齐 videos 的字段命名与软删除约定）
CREATE TABLE reports (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  task_type TEXT NOT NULL DEFAULT '',            -- 上传时选定，五选一
  tags_json TEXT NOT NULL DEFAULT '[]',
  object_key TEXT NOT NULL,                      -- reports/{id}/original
  original_name TEXT NOT NULL,
  content_type TEXT NOT NULL,
  file_size INTEGER NOT NULL DEFAULT 0,
  source_format TEXT NOT NULL DEFAULT '',        -- PPT | PPTX | PDF
  status TEXT NOT NULL DEFAULT 'UPLOADING',      -- UPLOADING | QUEUED | PROCESSING | READY | FAILED
  page_count INTEGER NOT NULL DEFAULT 0,
  pages_done INTEGER NOT NULL DEFAULT 0,
  fail_reason TEXT,
  convert_attempts INTEGER NOT NULL DEFAULT 0,
  converter_version TEXT,
  derived_pdf_key TEXT,                          -- reports/{id}/derived.pdf（PPT 转出的）
  created_by_email TEXT NOT NULL,
  created_by_name TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TEXT
);

-- 页：系统事实，只由转换脚本写
CREATE TABLE report_pages (
  report_id TEXT NOT NULL REFERENCES reports(id),
  page_no INTEGER NOT NULL CHECK (page_no > 0),
  thumb_key TEXT NOT NULL,                       -- reports/{id}/pages/p001.jpg   (≈480w)
  large_key TEXT NOT NULL,                       -- reports/{id}/pages/p001@2x.jpg (≈1600w)
  width INTEGER NOT NULL, height INTEGER NOT NULL,
  text_excerpt TEXT NOT NULL DEFAULT '',         -- pdftotext 首行/前 80 字，工作台的"页摘录"
  PRIMARY KEY (report_id, page_no)
);

-- 相关资料（第一部分的附件）
CREATE TABLE report_files (
  id TEXT PRIMARY KEY,
  report_id TEXT NOT NULL REFERENCES reports(id),
  object_key TEXT NOT NULL,                      -- reports/{id}/files/{fileId}/{name}
  original_name TEXT NOT NULL,
  content_type TEXT NOT NULL,
  file_size INTEGER NOT NULL,
  uploaded_by_user_id TEXT NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);

-- 版本链：每人一版，由数据库兜底
CREATE TABLE report_versions (
  id TEXT PRIMARY KEY,
  report_id TEXT NOT NULL REFERENCES reports(id),
  version_number INTEGER NOT NULL CHECK (version_number > 0),
  owner_user_id TEXT NOT NULL REFERENCES users(id),
  owner_name_snapshot TEXT NOT NULL,
  base_version_id TEXT REFERENCES report_versions(id),
  base_version_number INTEGER,
  base_payload_json JSONB,
  base_captured_at TIMESTAMPTZ,
  payload_json JSONB NOT NULL,
  content_hash TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 1 CHECK (revision > 0),
  payload_schema_version TEXT NOT NULL DEFAULT 'report-annotation/1',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (report_id, version_number),
  UNIQUE (report_id, owner_user_id),
  CHECK ((base_version_id IS NULL) = (base_version_number IS NULL))
);

-- 互动与评审：结构照抄视频侧三张表，只把外键换成报告
CREATE TABLE report_weekly_favorites (user_id, week_key, report_id, …, PRIMARY KEY (user_id, week_key));
CREATE TABLE report_version_ratings   (version_id PK, report_id, stars 1..5, rated_by_user_id, rated_by_name, …);
CREATE TABLE report_version_comments  (version_id, target_key, report_id, target_label, body, author_*, …, PRIMARY KEY (version_id, target_key));
```

全部新表 `ENABLE ROW LEVEL SECURITY` 并对 `anon`／`authenticated` REVOKE，与 `2026-08-12-enable-rls-all-tables.sql` 同一做法。迁移文件 `db/migrations/2026-09-XX-report-reverse.sql`，附加式、可重复执行，不动既有表。

### 3.3 版本 payload（`payload_schema_version = report-annotation/1`）

```ts
type ReportAnnotation = {
  background: { city; developer; projectBackground; businessBackground };   // 相关资料在 report_files，不进 payload
  strategy:   { narrative; model };                                         // model ∈ 四选一 | ''
  modules: Array<{ id; name; rel; role }>;
  units:   Array<{ id; mid; pid: string|null; name; rel; task; role; psy; concl }>;
  pages:   Array<{ n; mid: string|null; uid: string|null; transition; func; org; blocks: Block[] }>;
};
type Block = { id; name; x; y; w; h; type; roles: string[]; style; rel; narr; mark };  // 坐标为页图百分比
```

保存前的服务端校验（拒绝而不是修正）：
- `pages` 必须恰好覆盖 `report_pages` 的全部页号，各一条；
- 页的 `uid` 若非空，则该单元的 `mid` 必须等于页的 `mid`；`pid` 链不得成环、不得跨模块；
- 每个模块、每个单元（含子树）所辖页号必须连续；不存在无页且无子单元的单元、无页的模块；
- 组块坐标 0–100，宽高 > 0；固定选项字段取值必须在词表内；
- `revision` 乐观锁：请求带当前 revision，不等则 409（与 V1.9 同）。

**为什么段以"首页"锚定**：v2 把边界从 p22 挪到 p20，落到数据上只是 p20、p21 的 `uid` 变了；对比两版时按页号逐页比归属、条目、组块，不需要给段做 id 对齐。模块／单元的 `id` 只在一个 payload 内部有意义。

### 3.4 对象存储键
```
reports/{id}/original                      上传原件（PPT/PPTX/PDF）
reports/{id}/derived.pdf                   PPT 转出的中间 PDF（PDF 直传时不存在）
reports/{id}/pages/p{NNN}.jpg              缩略图 ≈480w，报告库封面（p001）、收纳框、左列
reports/{id}/pages/p{NNN}@2x.jpg           大图 ≈1600w，标注 modal 与 hover 预览
reports/{id}/files/{fileId}/{originalName} 相关资料
```
沿用 `getVideoBucket()`（本机 `LocalVideoBucket`，线上 COS）；命名上把它改叫 `getObjectBucket()` 顺手做，但不强求。

## 四、转换流水线（离线脚本）

`scripts/convert-report-pages.ts`，与 `backfill-thumbnails.ts` 同一台离线机运行；该机需装：LibreOffice（`soffice`）、poppler（`pdftoppm`、`pdftotext`、`pdfinfo`）、常用中文字体（思源黑/宋 ＋ 常见商用字体的替代映射）。

状态机：

```
UPLOADING ──complete──▶ QUEUED ──脚本领取──▶ PROCESSING ──全部页完成──▶ READY
                                                  │
                                                  └──任一步失败──▶ FAILED（fail_reason，可重试）
```

脚本循环（每次领一份，`SELECT … WHERE status='QUEUED' … FOR UPDATE SKIP LOCKED`）：
1. 下载原件到临时目录；`convert_attempts += 1`，状态 PROCESSING。
2. 若 PPT/PPTX：`soffice --headless --convert-to pdf`，产物上传为 `derived.pdf`。PDF 直传跳过。
   **要求是转换成功率，不是速度**，所以这一步按"能救就救"来写：
   - 超时 30 分钟（单次），超时或崩溃自动重试 2 次，每次重新拉起 soffice 进程（LibreOffice 卡死是常态，杀掉重来比等着靠谱）；
   - 第一次失败后第二次换 `--infilter` 强制按 PPT 97-2003／OOXML 解析，绕过自动探测误判；
   - 字体缺失不算失败：用 fontconfig 映射到已装的替代字体并在 `fail_reason` 之外的 `convert_notes` 里记录"第 n 页替换了字体 X"，卡片上不报错、工作台来源信息里可见；
   - 三次仍失败才 FAILED，`fail_reason` 写人能看懂的原因（文件损坏／加密 PPT／嵌入对象无法渲染），并给出"改传 PDF"入口。
3. `pdfinfo` 取页数 → 写 `page_count`。不设页数上限：235 页的策略大纲是真实存在的，超长只影响耗时，不该判失败；超过 300 页在报告库卡片上提示"页数较多，生成会慢一些"。
4. 逐页：`pdftoppm -jpeg -r <dpi>` 出两档 → 上传 → `pdftotext -f n -l n -layout` 取摘录 → 插入 `report_pages` → `pages_done = n`。逐页写库是为了报告库能显示"生成页图 118/262"。
5. 全部完成：READY。任何异常：FAILED + `fail_reason`（保留已生成的页，重试时可跳过已存在的页）。
6. 记录 `converter_version`（soffice 与 poppler 版本串），日后换渲染器可识别哪些报告需要重出图。

限制：原件 ≤ 200 MB；只收 `.ppt/.pptx/.pdf`（按扩展名 + content-type 双检）；上传页提示"版式要求高的建议直接传 PDF"。
每页出图也按同样原则：单页渲染失败（个别页有损坏对象）不拖累整份——该页用"渲染失败"占位图并记录，其余页照常，报告仍能 READY。

转换成功率的兜底顺序：LibreOffice 正常转换 → 换 infilter 重试 → 字体替换 → 单页降级 → 才是 FAILED。上线前用手头三份真实报告（红谷滩 .ppt、浦江镇 .ppt、北蔡 .ppt）加两份现代 .pptx 做回归，全部 READY 才算过。

## 五、接口

命名与 `app/api/videos/*` 平行，鉴权同样走 `requireApiUser` + `requireSameOriginMutation`。

| 方法与路径 | 作用 |
|---|---|
| `POST /api/reports` | 建条目＋签发原件的预签名 PUT；body：title、originalName、contentType、fileSize、taskType、tags |
| `POST /api/reports/[id]/complete` | 原件就位，状态 → QUEUED（仅原上传者） |
| `GET /api/reports` | 报告库列表：状态、进度、封面 URL（READY 才有）、版本摘要、任务类型、标签 |
| `GET /api/reports/[id]` | 详情：元数据＋全部页（缩略/大图签名 URL、摘录）＋相关资料 |
| `POST /api/reports/[id]/retry` | FAILED → QUEUED |
| `POST /api/reports/[id]/trash` | 软删除（同视频） |
| `POST /api/reports/[id]/files` ／ `DELETE …/files/[fileId]` | 相关资料：签发预签名 PUT／移除 |
| `GET /api/reports/[id]/annotation` | 当前版本链：默认最新版；含 canReview、评论、评分 |
| `PUT /api/reports/[id]/annotation` | 保存自己那一版：payload ＋ revision；无自己版本时按"基于当前看的版本"创建 |
| `GET /api/reports/[id]/annotation/versions` | 版本列表 |
| `POST /api/reports/[id]/annotation/versions` | 从某版创建自己的版本（每人一版，重复则 409） |
| `POST /api/reports/[id]/favorite` | 每周三票，投/撤；票满时 400 |
| `POST /api/reports/[id]/review` | 评分（0 撤销）与逐条目评论；仅评审人 |
| `GET /api/report-engagement?reportId=…` | 列表页批量取收藏数、我的投票、各版评分 |

服务层放 `lib/report-*.ts`；`lib/report-structure.ts` 收纳与 demo 一致的纯函数（编号、页码范围、连续性校验、连带集合、空段清理、已填完判定），**这一层要有单测**，demo 里跑过的那些用例直接搬成测试。

## 六、前端

### 6.1 报告库
`V04LibraryClient` 的 `REPORT` 页签接真数据；卡片、上传对话框、四种状态、按周／收藏／星级按报告库 demo。上传走"预签名直传 → complete"，与视频相同；上传完成后卡片以 QUEUED 插到最前，列表对 QUEUED/PROCESSING 的报告每 5 秒轮询一次进度（只在有未就绪项时）。

### 6.2 工作台 `/reports/[id]`
把 V2 demo 拆成组件，逻辑下沉到纯函数：

| 组件 | 职责 |
|---|---|
| `ReportStudioClient` | 外壳：顶栏（标题、来源、版本切换、撤销重做、保存状态、身份）、三部分折叠、自动保存与 409 处理 |
| `ReportPartOne` / `ReportPartTwo` | 两段表单；相关资料上传组件 |
| `ReportDeck` | 左页序＋分隔条＋右收纳框；选择、框选、搬运、落点预览、空段清理 |
| `ReportSectionPopover` | 模块／单元标注框：可拖、只有 × 关、开着时冻结 deck、hover 预览 |
| `ReportPageModal` | 页面与组块：页图框选、双向联动、翻页、彩色导航条 |
| `ReportMindMap` | 脑图 |
| `ReportGuide` | 分步引导 |
| 复用 | `V19AssignmentRating`、`V19ReviewComment`、`V19EditableValue`、`V04ChoiceField` 的样式与交互 |

撤销／重做在客户端以 payload 快照实现（demo 做法），保存只提交最新 payload。

### 6.3 开关与上线
- 环境变量 `REPORT_LIBRARY_UI_ENABLED`：关＝报告库页签仍是占位空态，接口 404。
- 上线顺序：迁移 SQL → 离线机装转换依赖并验证一份真实 PPT → 打开接口 → 打开 UI。
- 回退：关 UI 开关即可，数据不动。

## 七、验收标准

1. 上传一份 50 页 PPT：卡片依次经历 排队中 → 生成页图 n/50 → 就绪；封面为第 1 页；失败时原因可读、重试可恢复。
2. 工作台从零划出 5 模块／26 单元（含三级），页码范围、编号全部正确；任何会打断连续性的搬运被拒绝且有提示；空段自动撤销。
3. 两个人各自成版；v2 挪动边界后，版本对比按页列出差异；v1 内容不受影响。
4. 评论仅评审人可写、锚定版本；评分未打时非评审人不见；再点撤销。
5. 报告库每人每周三票，一票一份报告；票满时第四票被拒；未就绪报告不可收藏、不可进入。
6. `lib/report-structure.ts` 单测覆盖：编号、范围、连续性、连带（左／右／退回）、空段清理、已填完判定。
