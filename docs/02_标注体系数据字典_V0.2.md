## 1. 适用范围

本文将 V0.2 表格结构转换为产品和工程可执行的数据定义，但不修改任何字段含义。

## 3. 标注答案通用结构

表格中的列是通用展示槽位，不代表所有字段含义完全相同。系统内部不能只保存 `column_c`、`column_d`，应保存带业务角色的答案。

```text
FieldAnswer
├── field_code
├── taxonomy_version_id
├── primary_selections[]
├── secondary_selections[]
├── auxiliary_selections[]
├── language_perspective
├── image_perspective
├── terminal_turn
├── structured_supplement
├── custom_value
├── evidence
└── note
```

通用要求：

- 每个选项保存稳定 `option_id`，同时保留当时显示名称快照；
- 主、副、辅助、语言视角、影像视角、终极转折等角色单独保存；
- “结构补充”保存强度、数量、位置、修饰词和其他结构信息；
- “其他（自定义）”必须填写 `custom_value` 和必要说明；
- `evidence` 可引用一个或多个镜头 ID、时间段及文字依据。

## 4. 原始信息与核心判断

| 字段 | 类型 | 说明 |
|---|---|---|
| 广告标题／片名 | 短文本 | 作品标题 |
| 商业意图 | 长文本 | 作品希望完成的商业目标 |
| 创意母题 | 长文本 | 核心创意命题 |
| 创意思维链 | 长文本 | 从商业问题到创意表达的推导 |
| 故事梗概 | 长文本 | 全片故事概述 |
| 全篇创意总结 | 长文本 | 对全片创意、故事、文案和视听关系的总结 |

这些字段属于每套标注结果，不能只放在案例公共元数据中，因为不同标注者可能给出不同判断。

- 规则：主类型 1 项＋副类型不超过 1 项；必要时补充强／中／弱。

### A3 商业作用对象

- 回答的问题：创意最终服务于哪一类商业对象，并具体作用到其中哪一层？
- 规则：商业大类 1 项＋具体落点 1–2 项；品牌、产品、服务分层选择。

| 类别 | 选项 | 说明 |
|---|---|---|
| 商业大类 | 品牌 | 创意主要改变、建立或强化品牌层面的认知与关系 |
| 商业大类 | 产品 | 创意主要解释、证明或放大产品本身的价值 |
| 商业大类 | 服务 | 创意主要表达服务内容、能力、体验或承诺 |
| 品牌落点 | 品牌理念／价值主张 | 让品牌所相信、主张或代表的价值获得表达 |
| 品牌落点 | 品牌角色／用户关系 | 定义品牌在用户生活、社会或关系中的角色 |
| 品牌落点 | 品牌形象／个性 | 塑造品牌的气质、性格、态度或可识别形象 |
| 品牌落点 | 品牌信任／声誉 | 建立可信度、专业性、责任感或长期声誉 |
| 产品落点 | 产品核心功能 | 围绕产品最关键的功能与用途展开创意 |
| 产品落点 | 产品极致性能 | 放大速度、强度、精度、耐久等可达到极限的性能 |
| 产品落点 | 产品利益／问题解决 | 把功能转化为用户能够感知的实际利益与问题解决 |
| 产品落点 | 产品应用场景 | 通过具体生活、工作或使用情境呈现产品价值 |
| 产品落点 | 使用方式／习惯依赖 | 作用于使用动作、使用频率、习惯形成或持续依赖 |
| 产品落点 | 产品体验／感受 | 突出使用过程中的感官、情绪或总体体验 |
| 服务落点 | 服务内容／解决方案 | 说明服务提供什么以及解决什么问题 |
| 服务落点 | 服务能力／专业性 | 突出专业能力、效率、资源或服务保障 |
| 服务落点 | 服务过程／体验 | 呈现客户在服务流程中的具体感受与体验 |
| 服务落点 | 服务关系／承诺 | 表达陪伴、保障、响应、责任或长期承诺 |

工程校验：

- 先选商业大类，再选与之兼容的具体落点；
- 品牌大类默认只显示品牌落点；
- 产品大类默认只显示产品落点；
- 服务大类默认只显示服务落点；
- 自定义落点必须记录归属的商业大类；
- 如业务需要跨大类表达，应记录为明确例外，不通过错误选项组合实现。

## 6. 故事组织 B1–B10

### B1 叙事形态

- 回答的问题：作品以什么基本形态组织内容？
- 规则：主形态 1 项；必要时可用组合表达。
- 选项：完整故事、微型事件、情境片段、人物历程、观点叙事、概念蒙太奇、产品演示、非叙事奇观。

### B2 故事参照类型

- 回答的问题：这条片子整体借用了哪一种人类熟悉的故事经验？
- 规则：主参照类型 1 项＋副参照类型不超过 2 项；允许开放新增。
- 选项：
  - 青春怀旧、家庭亲情、成长陪伴；
  - 爱情相遇、爱情错过、离别重逢、家庭和解；
  - 公路旅程、职场奋斗、热血竞技、小人物逆袭；
  - 日常生活喜剧、荒诞喜剧、悬疑揭秘、社会纪实；
  - 人生回望、童话寓言、科技奇幻、历史史诗、英雄冒险、群像人生；
  - 其他（自定义参照类型）。

### B3 故事原型

- 回答的问题：故事在讲一种什么基本变化？
- 规则：主原型 1 项＋副原型 1 项。
- 选项：追寻、回归、成长、相遇、离别、守护、和解、拯救、发现、传承、日常显影、对抗。

### B4 时间结构

- 回答的问题：故事怎样组织时间？
- 规则：主结构 1 项＋辅助结构。
- 选项：单线顺叙、倒叙进入、闪回嵌套、双时空交织、多阶段跳跃、平行时间、逆序叙事、循环结构、碎片拼合、时间停滞／压缩。

### B5 叙事视角

- 回答的问题：谁在讲述，影像又主要跟随谁？
- 规则：分别标注语言视角和影像视角；二者可以不同。
- 选项：第一人称回忆、第一人称当下、第三人称限知、第三人称全知、客观观察、多人物视角、见证者视角、品牌／产品视角。

工程实现必须设置两个独立角色槽位：

- `language_perspective`；
- `image_perspective`。

### B6 情节发动方式

- 回答的问题：什么力量推动故事往前走？
- 规则：主发动方式 1 项＋辅助方式 1 项。
- 选项：目标驱动、关系驱动、事件驱动、秘密驱动、误解驱动、选择驱动、重复变化驱动、状态累积驱动、观点推演驱动。

### B7 信息释放结构

- 回答的问题：观众按照什么方式获得事实和意义？
- 规则：主结构 1 项＋辅助结构 1 项。
- 选项：直接展开、延迟解释、悬念揭示、身份揭示、因果揭示、意义重释、误导反转、层层加码、开放留白。

### B8 节奏结构

- 回答的问题：全片力量怎样在时间中分配？
- 规则：选择 1–2 个主标签；必要时补充结尾节奏变化。
- 选项：匀速推进、逐级加速、逐级放缓、松紧交替、前慢后快、前快后慢、脉冲式、单峰式、双峰式、平台式。

### B9 转折结构

- 回答的问题：故事在何处、以什么方式改变方向或意义？
- 规则：采用“转折类型＋数量＋终极转折”的组合标注。
- 选项：行动转折、情境转折、关系转折、情绪转折、认知转折、意义转折、品牌转折。

工程实现至少保存：

- 转折类型列表；
- 转折数量；
- 转折位置或时间码；
- 终极转折；
- 标注依据。

### B10 结尾类型

- 回答的问题：影片最终以什么方式完成或留下意义？
- 规则：主结尾类型 1 项＋辅助类型；明确最终落点。
- 选项：事件完成、关系确认、真相揭示、意义升华、回环重现、品牌解释、金句封口、开放留白、行动号召。

## 7. 逐镜头脚本

每个镜头一条记录，镜头组通过重复组 ID 或组名表达，不依赖合并单元格。

| 分组 | 字段 | 建议类型 |
|---|---|---|
| 故事时间线 | 镜头组序号／名称 | 文本＋可选组 ID |
| 故事时间线 | 镜头序号 | 整数或显示序号 |
| 故事时间线 | 时间段 | 开始毫秒＋结束毫秒 |
| 镜头安排 | 景别 | 文本，后续可词表化 |
| 镜头安排 | 机位／角度 | 文本，后续可词表化 |
| 镜头安排 | 镜头运动 | 文本，后续可词表化 |
| 故事&情节 | 画面内容（镜头故事） | 长文本 |
| 语音 | 对白 | 长文本 |
| 语音 | 旁白 | 长文本 |
| 字幕／屏幕文案 | 字幕／屏幕文案 | 长文本 |
| 声效 | 声效 | 长文本 |
| 音乐 | 音乐 | 长文本 |
| 创意标注 | 创意点评／标注依据 | 长文本＋可选字段引用 |

每条镜头记录应有稳定 UUID，显示序号仅用于排序和展示。

界面按镜头组呈现时，第1列“镜头组序号／名称”和第13列“创意点评／标注依据”采用纵向合并栏；第2–12列仍严格逐镜、逐字段显示，不得合并。为兼容现有逐镜存储结构，新的镜头组级点评写入该组首镜头的 `creativeComment`，读取历史数据时汇总同组所有非空点评，字段含义不变。

## 8. 前端控件规则

附表A、附表B是A1–A9、B1–B10预设选项的权威来源。界面不得自行改写或补造专业选项；通用“其他（自主输入）”仅作为开放填写入口，不作为新的专业词表值。

| 场景 | 控件 |
|---|---|
| 固定单选 | 单选下拉或单选卡片 |
| 主＋副选择 | 分离的主标签和副标签控件 |
| 有数量上限的多选 | 多选控件＋剩余数量提示 |
| A3 分层选择 | 商业大类单选＋具体落点级联多选 |
| A5 修饰词 | 主基调单选＋自由修饰词标签 |
| B5 双视角 | 语言视角与影像视角两个独立下拉 |
| B9 组合标注 | 类型多选＋数量＋位置＋终极转折 |
| 自定义选项 | 选择“其他”后强制显示文本和说明 |
| 标注依据 | 长文本＋镜头／时间码引用 |

演示纵切版采用兼容式实现：预设值以悬停浮窗中的可选项呈现，点击后写入原有字段答案；文本框始终开放，历史自由文本无需迁移。后续如需分别统计主标、副标、辅助项和结构补充，再在不改V0.2含义的前提下增加结构化存储。

## 9. 版本迁移规则

### V0.1 到 V0.2

不能按行号或显示位置迁移。

关键差异：

- V0.1 A3“创意作用对象”在 V0.2 拆为 A3“商业作用对象”和 A4“叙事作用对象”；
- V0.1 A4–A8 在 V0.2 顺延为 A5–A9；
- V0.2 A3 引入商业大类及分层落点；
- V0.2 明确 A4 与 B2 的边界。

迁移策略：

1. V0.1 记录继续绑定 V0.1，不修改原始结果；
2. 如需转为 V0.2，创建新的迁移草稿；
3. A1、A2 可在确认选项未变后映射；
4. V0.1 A3 必须人工重新判断并拆成 V0.2 A3/A4；
5. V0.1 A4–A8 按稳定含义映射到 V0.2 A5–A9；
6. 迁移结果必须记录来源版本、执行人和确认状态；
7. 未经人工确认的迁移结果不得进入正式共识。

## 10. 完整性校验

提交前至少检查：

- 存在非空体系版本；
- A1–A9、B1–B10 字段定义来自同一版本；
- 主标签数量符合规则；
- 副标签和辅助标签不超限；
- A3 大类与落点兼容；
- A4 与 B2 分别填写；
- B5 两类视角分别保存；
- B9 的类型、数量、位置和终极转折结构完整；
- 自定义选项有文字说明；
- 镜头时间段合法；
- 标注依据引用的镜头存在；
- 提交快照包含字段和选项显示名称，避免后续版本变更导致历史不可读。
